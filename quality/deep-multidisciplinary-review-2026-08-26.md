# 咔嚓 OpenMontage 启发迭代：深度多专业复核与修复记录

## 复核结论

本轮不是对功能清单做表面确认，而是沿真实执行边界复核 Capability Broker、费用
账本、MiniMax 外部视觉调用、参考片派生、素材 corpus、制作飞行记录、制作模式
路由、工作流包和 Studio 观察面。共确认 11 组问题，其中高风险 5 组、中风险 6 组；
代码与定向回归已修复，最终全量、安装和证据门禁以本文末尾的最终验证记录为准。

本记录由实现者自审产生，因此所有修复在独立复核完成前均为 `fixed_unverified`，
不得解释为发布就绪、外部提供者已验证或真实生产闭环。

## 专业视角与判断

| 视角 | 主要问题 | 修复后的产品含义 |
| --- | --- | --- |
| 产品与业务 | “有预算记录”不等于“一次调用一次授权”；参考片权利状态也不等于可派生 | 将用户意图落实为一次性费用许可和明确用途许可 |
| 架构 | 注册表、决策和执行器之间存在可被漂移或篡改的松散边界 | 在每一层冻结身份并在下一层重新验证，不信任上游自述 |
| 安全与隐私 | 任意命令模板、越界符号链接和原始诊断文本可能扩大本机执行或泄露面 | 命令白名单、realpath 边界、限量读取和输出脱敏 |
| 数据与检索 | corpus 曾信任旧 media index 和旧源 SHA | 构建与校验都重验索引摘要、源身份、时长和片段范围 |
| 可靠性与成本 | 付费预占可重复使用；调用失败后的费用状态不明确 | 原子消费后进入 `reconciliation_required`，成功或失败都必须按账单对账 |
| UI/交互/可访问性 | Studio 观察接口和动态事件列表缺少显式只读信号与更安全的渲染方式 | 本地读请求头、DOM 文本节点、状态 allowlist 与 `aria-live` |
| 测试与交付 | 初轮回归未覆盖重放、篡改、漂移和链接越界 | 增加攻击性回归；深审后重新执行全量与双端安装同步 |

## 已确认并修复的问题

### MDR-001 高：付费预占可跨多次外部调用复用

- 根因：执行器只读取账本条目，没有在调用边界原子改变状态。
- 风险：一个获批预算条目可授权多次真实 cache miss，实际费用超出用户意图。
- 修复：增加 `cost consume`，在文件锁内把未使用的 `reserved/approved` 转换为
  `reconciliation_required`，冻结 `executionId` 和执行意图 SHA-256；第二次消费失败。
- 失败策略：确认执行器存在后才消费；外部调用一旦开始，无论成功或失败都保留
  待对账状态，避免失败响应被误当作零费用。
- 回归：覆盖首次消费、重复消费阻断、消费后对账和 MiniMax cache miss 门禁。

### MDR-002 高：费用账本可被不一致审批或退款字段污染

- 根因：状态校验偏重流程命令，没有完整验证持久化条目内部不变量。
- 风险：手工篡改 `approvalRequired`、审批证据或退款金额后可能抬高可用预算。
- 修复：由阈值重新计算审批要求；高额条目的后续状态持续要求审批证据；退款不得
  为负、不得超过实际费用，`refunded` 必须具有正退款额。
- 回归：覆盖伪造退款、审批状态不一致和预算上限。

### MDR-003 高：参考片“权利状态”可被误当作派生授权

- 根因：旧合同只判断 `rights.status != unknown`，没有区分分析用途和派生用途，
  也未要求许可/合理使用审查证据。
- 风险：标记为 `licensed` 或 `fair-use-review` 的素材可能在无证据时生成派生方案。
- 修复：增加 `permittedUse` 与 `derivationAllowed`；许可和合理使用审查只有在
  `principle-derivation` 且存在证据时才可派生；`analysis-only` 始终失败关闭。
- 防漂移：validate/derive 重新核验当前源文件强身份、权利字段、必需完整性摘要和
  派生边界；删除摘要不能降级为“无需校验”。

### MDR-004 高：素材 corpus 可继续信任陈旧索引与已变化的源文件

- 根因：片段保存了源 SHA，但 build/validate 没有系统地把当前索引和当前文件
  重新绑定。
- 风险：检索结果的时间段、许可、文本或运动证据可能来自旧文件。
- 修复：构建前验证 index 类型、版本和摘要；校验时重新读取 index、计算源 SHA、
  探测当前时长并检查所有片段边界；corpus 摘要必须存在；空 corpus、空检索词和
  非对象 JSON 根节点失败关闭。
- 回归：复制真实媒体建库后篡改源文件，旧 index 的 build 和旧 corpus 的 validate
  均必须失败。

### MDR-005 高：制作飞行记录可能泄露敏感诊断并跟随项目外输入

- 根因：观察器假设所有项目日志已经脱敏，并对 JSONL/目录读取缺少资源上限和
  realpath 信任边界。
- 风险：API key、token、password 等进入快照；符号链接可把项目外 JSON 纳入
  Studio；异常大日志造成本地资源压力。
- 修复：对公开字段做幂等脱敏和长度压缩；限制单文件、单源、目录和总事件数；
  拒绝符号链接和项目外 realpath；快照验证再次检查敏感模式与来源计数。
- 回归：覆盖密钥脱敏和项目外 decisions 符号链接拒绝。

### MDR-006 中：工作流包变量和命令模板缺少严格形状约束

- 根因：结构化变量可被字符串化成 `[object Object]`，模板合同未充分禁止 shell
  操作符和未知 Kacha 命令。
- 风险：产生不可执行清单，或把可扩展 JSON 变成本机命令注入面。
- 修复：requiredInputs 唯一且必须被引用；变量只接受单行标量；模板只允许已知
  `kacha` 子命令并拒绝 shell 控制符；输出路径不得覆盖变量或注册表。

### MDR-007 中：能力注册表可能高估不可执行或越界的提供者

- 根因：provider schema、probe 参数、workspace binary 和系统命令路径的边界不足。
- 风险：结构错误仍参与排名，或符号链接把 workspace binary 指向 skill 外部。
- 修复：校验模式、隐私、许可、布尔能力、成本、权重和 runtime 形状；系统探测只
  使用受信目录，workspace binary 用 realpath 约束；决策显式输出证据新鲜度。

### MDR-008 中：制作模式决策可被篡改成不合格的选中引擎

- 根因：旧 validate 更偏 JSON 形状，没有重新证明 chosen provider 合格且与 handoff
  一致。
- 风险：被修改的 decision 仍可能流向后续制作。
- 修复：嵌入并验证原始请求；chosen 必须存在、eligible 且无 exclusions；blocked
  不得带执行 handoff；handoff provider 和能力摘要必须一致；决策摘要不可省略。

### MDR-009 中：Studio 飞行记录面缺少更强的本地只读与安全渲染语义

- 根因：GET 接口只依赖同源检查，动态列表用 HTML 字符串拼装，状态更新没有
  live-region。
- 风险：虽然原实现进行了转义，但安全性依赖单一辅助函数；辅助技术不能及时获知
  加载或错误状态。
- 修复：API 增加 `X-Kacha-Studio: 1` 读标识；前端统一发送该标识；事件列表改用
  `createElement/textContent/replaceChildren`，状态类使用 allowlist，并增加
  `aria-live="polite"`。

### MDR-010 中：公开验证记录依赖本机绝对路径和外部 AppCreate 模块

- 根因：结构化审查工具只在开发者机器的外部 `PYTHONPATH` 存在时才能完整校验，
  验证记录还直接保存了本机目录和备份绝对路径。
- 风险：GitHub 检出无法复现审查门禁，并暴露无必要的本机目录结构。
- 修复：把最小、可移植的证据校验器纳入 `tools/appcreate_evidence.py`，迁移清单显式
  声明该文件；命令改为仓库内相对调用，备份引用改为不含路径的本地 opaque ref。

### MDR-011 中：受保护基线文件的身份记录与真实工作树不一致

- 根因：变更审查记录引用了不存在的旧文件名，并保存了无法对应当前受保护文件的
  SHA-256。
- 风险：后续复核可能把身份漂移误判为已证明的“未触碰”，削弱对用户既有改动的
  保护证据。
- 修复：按真实路径重新登记三份既有动态字景文件的基线 SHA-256；提交前门禁随后
  仅移除实施记录中的一个行尾空格换行，并把变更前后摘要与 `semanticImpact: none`
  单独写入 `postReviewNormalizations`，不把格式归一化伪装成“未触碰”。

Codex/Claude 安装摘要。独立复核通过前，结构化完成状态保持 `in_progress`。
