## 剪辑逻辑

### 1. 以语义拍驱动画面，不以固定秒数加效果

参考视频的常态不是每隔几秒随机换包装，而是每个短语义单元完成一次“进入—停稳—退出”。普通说明段约 0.8–2.4 秒形成一个可见变化；开场和反差段更密，教程操作段更慢。

触发顺序：

1. 先判断信息、情绪或视角是否变化；
2. 再判断本句的逻辑重音；
3. 只为这个变化选择一种主效果；
4. 让动作在重读词前 0–2 帧启动，在词落下时到达峰值；
5. 下一语义拍开始前，上一组非持续元素先退出。

### 2. “网感”主要来自空间关系变化

高频机制是尺度、位置、遮挡、前后景、容器形状和阅读路径的变化。贴纸、花字和音效只负责把关系说清楚，不能代替关系本身。

可复用的空间语法：

- 重要：推近、放大、占据中心；
- 否定或退缩：缩小、移入负空间；
- 多观点：人物让位，项目逐个建立；
- 证据：证据占主画面，人物保留画中画；
- 聚焦：背景压暗或虚化，目标区域保持清晰；
- 纵深：背景、框架、人物使用不同速度和遮挡关系；
- 并列：当前项最强，完成项保留但降级。

### 3. 每个效果都有完整状态

任何组件必须至少有：

- `entry`：为什么从哪里进入；
- `peak`：口播重音落在哪一帧；
- `hold`：观众需要多少阅读时间；
- `exit`：何时、向哪里退出；
- `fallback`：素材、蒙版或安全区不满足时如何降级。

只有出现动画没有退出动画，会造成参考视频返工中常见的“切回真人时附加元素还没消失”问题。

### 4. 音效只给动作定标

音效峰值应落在元素完成落位、形状切换完成或镜头到达终点的帧上。一个语义拍最多一个主音效；连续小元素可使用更轻的同类音效，但不能连环轰炸。人声永远优先。

### 5. 参考风格与产品风格分离

`config/effects/z-en-netstyle.json` 保存机制、触发、失败模式和验收；颜色、字体、圆角、阴影、边框与字幕位置继续由视频设计系统解析。这样可以复现同一种运动和层次，而不复制参考创作者的视觉资产。

## 使用边界

- 不因为“想更有网感”就自动套满全部效果；
- 同一段只有信息、情绪或视角变化时才切换主机制；
- 人脸、字幕、品牌和平台 UI 安全区优先级高于装饰；
- 真实证据素材必须来源可追溯，语义不匹配时不用；
- 人物蒙版覆盖不足、边缘严重抖动或跟踪丢失时，降级为普通卡片、画中画或景别切换；
- 任何参考视频分析副本都只用于本地研究，不进入仓库、Release 或公开安装包。

## 生产决策表

生产系统使用 `config/effects/production-motion-policy.json` 固化语义路由：
说重点用 `semantic_importance_zoom`，负面词用 `semantic_negative_shrink`，
突出局部用 `semantic_mask_emphasis`，多观点用 `semantic_viewpoint_clones`，
事实、数据和案例用 `semantic_evidence_insert`，需要移动让位用
`semantic_keyframe_reposition`，创意类比用 `semantic_graphic_morph`。
这些是默认决策，不是机械关键词替换；语义不成立时保持主画面或提交完整自定义
合同。

空间变化按四条路径选择：`space_focus_route` 用蒙版移动视觉焦点；
`space_frame_between_layers` 把边框或贴纸放在背景与人物之间并制造视差；
`space_text_depth_wrap` 用文字尺度、位置、遮挡和动画建立近远层次；
`space_paper_demo_stage` 抠出人物、替换背景并逐项加入演示素材。所有层都必须
动态避让人物、字幕、常驻品牌和平台 UI，且画面、语音、动作与声音表达同一意图。

## 代表素材实测与修正

能力形成的最低要求是：每种效果至少在一条构图和语义都适合的代表视频上完成
真实渲染与正常速度复核，不要求同一效果机械地在两条视频上重复验证。本轮为
额外检查跨构图与跨帧率稳定性，33 个机制分别在两条竖屏真人视频上完成了全量
渲染，覆盖 29 fps 与 30 fps、人物大小变化、复杂与简单背景、人物蒙版以及
有声输入。发现并修正了以下实现问题：

| 问题 | 根因 | 固化后的处理 |
|---|---|---|
| 人物后标题被人物完全挡住 | 文字层与人物层没有真实分离 | 先用逐帧人物蒙版重建前景，再按背景、文字、人物顺序合成 |
| 变形开场只有文字变化，空间变化不明显 | 容器轮廓没有形成视觉对照 | 矩形与圆形遮罩按节拍切换，背景同时降权 |
| 同一效果在 29/30 fps 上峰值偏移 | 运动按固定帧数计算 | 所有 entry/peak/exit 改为按归一化进度计算 |
| 多段样片拼接出现重复 DTS | 对独立编码片段直接 stream copy | showcase 统一重建 CFR 时间基和 48 kHz 音频时间轴 |
| 组件标题被人物前景遮挡 | 说明标签落在主体高频区域 | 示例说明统一移到顶部安全区，正式项目仍由碰撞系统选位 |
| 并列项一次全部出现，观众先读完 | 缺少当前项状态 | 逐项建立；当前项用暖金色，已完成项保留并降权 |
| 装饰与动作音效错位 | 音效绑定区间而不是落点 | 音效只绑定元素落位、形变完成或镜头终点 |

每条承担验收任务的 showcase 必须满足：所分配机制齐全、输出尺寸与源片一致、
音频存在、全片可解码、无黑段、无非单调时间戳，人物蒙版效果有实际遮挡关系。
多素材回归只在要验证跨构图、跨帧率或跨素材稳定性时追加。该测试证明实现可
运行；正式成片仍需按内容触发逐项选择并正常速度审片。

## 运行与验收

### 正式成片

正式应用不是把 showcase 拼进成片，而是把最终文稿中的语义拍编译为独立
时间线合同：

```bash
node scripts/kacha.mjs netstyle plan \
  --input PICTURE_LOCK.mov \
  --transcript FINAL_TIMED_TRANSCRIPT.json \
  --mask PERSON_MASK.mkv \
  --output NETSTYLE_PLAN.json
node scripts/kacha.mjs netstyle validate-plan --plan NETSTYLE_PLAN.json
node scripts/kacha.mjs netstyle render-plan \
  --plan NETSTYLE_PLAN.json \
  --sfx-root /path/to/project-sfx-library \
  --output VISUAL_PACKAGED.mov
```

带时间文稿接受 JSON、SRT；JSON cue 可提供：

- `start`、`end`、`text`：真实口播区间和文本；
- `effectId` / `netstyleEffectId` / `visualIntent`：显式选择任一注册机制；
- `display.title`、`display.subtitle`、`display.items`：当前内容，不使用演示文案；
- `assetRef`：证据卡使用的真实图片或视频；
- `sfxLevelDb`：相对人声的事件音效电平。

未显式指定时，规划器只对开场问题、并列清单、真实证据、否定、观点变化、
结论重音和局部聚焦使用确定性语义规则；无法证明触发时不加效果。规划器按
源片有效帧率量化边界，限制每 10 秒主效果密度和最小间隔，并确保同一时刻
最多一个主效果。需要人物前后层次的机制必须有逐帧人物蒙版；证据卡必须有
真实 `assetRef`，否则阻断或降级。

计划冻结源视频、带时间文稿、人物蒙版、证据素材、当前设计系统和效果注册表
摘要。`validate-plan` 会拒绝过期摘要、缺失素材、重叠主效果、无效帧边界和
错误 SFX 电平。`render-plan` 只在效果区间重建画面，随后按统一 CFR 时间基
合成完整视频；原人声保持 unity gain，SFX 峰值绑定事件 `peakFrame`。输出
manifest 记录真实应用事件、资源、哈希、解码、几何、帧率、时长与演示标签
禁用结果。项目 manifest 使用 `plans.netstyleTimelines` 登记计划。

增量返工可使用 `recipe=netstyle`，并通过 `parameters.effectId` 或
`parameters.plan` 指向机制或正式计划；它只失效对应视觉区间、SFX stem 和
最终视频，不应重跑无关内容精剪、dialogue 或封面。

### 能力预览与回归

```bash
node scripts/kacha_netstyle.mjs list
node scripts/kacha_netstyle.mjs validate
node scripts/kacha_netstyle.mjs preview \
  --input INPUT.mp4 \
  --effect hook_title_behind_subject \
  --mask PERSON_MASK.mkv \
  --output preview.mp4
node scripts/kacha_netstyle.mjs showcase \
  --input INPUT.mp4 \
  --mask PERSON_MASK.mkv \
  --output showcase.mp4
```

`preview` 用于单项能力复核；`showcase` 会把注册表中的手法逐项渲染。默认
每种效果在一条合适的代表视频上验证即可；只有跨构图、跨帧率或跨素材风险
较高时才追加第二条。正式项目仍必须先写清触发理由，不能把 showcase 当成
自动剪辑模板。
