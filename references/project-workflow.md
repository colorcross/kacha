# 项目工作流

新建通用和大灰AI工程采用 `workflowPolicy.version=adaptive-v1`。没有该字段的旧工程保留旧执行顺序与声音要求；只有实际处理旧工程时读 `references/legacy/project-workflow-v2.md`。历史规则不能进入新工程作为额外数量目标。

## 一个目标，四个用户步骤

理解任务与素材 → 形成可播放初稿 → 针对问题修改 → 验证并交付。

这四步是用户视图，后台按真实依赖推进。Agent 可在同一次内容理解中决定结构、保留/删除、切点、插镜和声音；不为重复说明同一判断创建多轮模型任务。简短口播无需自动展开成长片制作流程；长片保留全片论证索引，再深入相关段落。

`editProposal` 记录一次用户目标、授权、真实源、几何约束、内容决定及实际启用的模块。不适用模块保留简明理由。adaptive 工程可省略 `executionFlow`，脚本从该方案派生节点、依赖和不适用状态，不要求模型手工维护十三项重复进度。具体镜头、字幕和声音写入 Timeline IR；导演/质量视图引用这些事实，不重复创造另一份时间线。

## 依赖与完成

`next` 返回当前建议及 `availableStages`。封面在素材盘点后即可开始；精剪与对白处理可独立推进；连接检查必须等精剪和对白处理完成；预览依赖实际画面、字幕、混音与连接检查；最终交付仍依赖完整技术QC和封面检查。

每项完成使用当前 `--expected-input` 与真实 evidence 登记。并行只限独立任务，各重型任务仍受主机资源锁约束。先验证依赖再记录；旧任务迟到不能覆盖新输入。修改只失效相关节点及其下游，源身份、品牌、授权或运行时变化按完整影响处理。

对已有批准基线的小改动继续使用 v3 增量路径；结构变化走工程依赖重新计算。新工程不自动迁移旧工程。旧候选或审阅不能因新默认而获得通过。

## 必须保留的结果要求

- 源只读，新输出独立。没有明确要求时保持源几何、帧率与色彩。
- 切点保留句意、否定、条件、数字、因果和真实时序；开场按实际叙事完成，不凑动效配额。
- 来源/许可、字体、真实声画和媒体身份可核验；生成图不替代事实证据。
- 人声先诊断。只有当前源的诊断与审听支持时才采用直通或轻处理；明确要求分离或混有背景音乐的材料仍执行分离。
- 新BGM默认MiniMax Audio网页；含音频的视频默认MiniMax Design。未知提交先查任务与费用状态。
- 当前实际产物的技术QC、正常速度审阅及发布权限分别验证；计划、状态完成和渲染成功都不替代终审。

## 按影响加载

只读取当前涉及的声音、字幕、素材、视觉或大灰栏目合同。强模型优先连续完成判断，弱模型/困难任务可用 guided；按实际能力与上下文选择，不能以客户端名称判断。素材全文、逐词时间戳与日志留在可检索文件中，避免重复转述。
