# 内容、切镜、节奏与效果理论

## 内容完整性

- 句子、数字、专名、否定、条件、因果和结论必须完整；
- 长停顿只压缩无声本体，保留呼吸、表情和必要留白；
- 重复表达保留信息更完整、画面更自然的一次；
- 口误可以删，但前后主谓、指代、数字和逻辑不能断裂；
- 每个连接点必须以正常速度试听，不能只看波形或时间线。

最终字幕和内容判断以最终音频为第一依据，原稿只用于专名、数字、术语和上下文校准。

## 留存结构

复杂项目建立 `retentionMap`：

- `openingPromise`：首个完整语义单元建立问题、冲突、收益或强画面；
- `openLoop`：只留下最终会兑现的问题；
- `reHooks`：只在章节转换、认知升级或情绪换挡时重新聚焦；
- `payoff`：明确观众最终得到什么；
- `ending`：自然收束、行动邀请或真正成立的循环。

不按固定秒数机械插钩子，不用虚假悬念。没有真实平台数据时，只能提出可测试假设，不能声称会提升完播或成为爆款。

## 景别语法

- 远景/全景：空间、环境、人物关系；
- 中景：动作、身体语言、稳定讲述；
- 近景：表情、态度、物品和信息细节；
- 特写/大特写：眼神、手、数字、文字和强落点；
- 插镜、图解、主观镜头单独标记，不伪装成景别。

同一主体、同一连续语义段，相邻镜头必须产生手机尺寸可感知的景别变化。不同主体或不同观察位置可以使用相同景别，不能被验证器误判为“近景接近景”。

优先使用真实机位、补拍、动作细节和 B-roll。数字重构图必须保护清晰度、头顶、眼睛、手势、证据物、字幕和平台安全区。只改变 2%–5% 的缩放不算换景别。

### 人物头部完整性

切镜不等于随意放大裁切。只要镜头中有人，切前和切后都分别检查：

- 普通远景、全景、中景和近景必须保留完整头发，并至少留出约画面高度 1.5% 的可见头顶余量；
- 人物移动、点头、前倾时检查整个有效区间，不只看第一帧；
- 多人画面逐人检查，不能为了保住主讲者而切掉另一人的半个头；
- 只有明确服务眼神、嘴型、手部或细节的特写/大特写，才允许有意裁切头部，并记录构图意图；
- 数字推近造成头发贴边、头顶消失或脸被平台 UI 挤压时，优先减小推近、调整锚点、改用真实插镜或不切。

`cutSheet` 使用 `humanPresenceBefore/After`、`headFramingBefore/After` 和
`headTopMarginBefore/After` 记录切点两侧。特写例外使用
`intentional_extreme_close`，并写明 `extremeCloseIntent`。

## 切镜三大理由

每个切点至少满足一项：

1. `information`：信息对象或信息层级变化；
2. `emotion`：表演、构图或声音形成真实情绪变化；
3. `perspective`：观察位置、人物视角或认知立场变化。

复杂项目建立 `cutSheet`，记录：

- 时间、切前/切后源段；
- `subjectBefore / subjectAfter`；
- `shotScaleBefore / shotScaleAfter`；
- `cutReason` 与具体 `change`；
- 动作、视线、呼吸、语义、声音或节拍锚点；
- 连续性处理；
- 失败条件和 QC 证据。

使用：

```bash
node scripts/validate_edit_plan.mjs edit-plan.json
```

验证器会解析 timecode，检查时间顺序，并只在“同一主体相邻景别相同”时拒绝，而不是机械禁止所有相同景别。

## 切点与转场

切点优先落在：

- 新语义单元；
- 动作峰值；
- 视线转移；
- 呼吸结束；
- 情绪转折；
- 明确声音事件。

固定机位跳切优先用真实景别变化、动作切、J/L-cut、声音桥、短插镜或图解吸收。转场只有在时间、空间、动作、图形、声音或情绪存在连续关系时使用。说话嘴型上的溶解、无动机鞭甩、模板擦除和随机变焦均回退为干净切。

### 切法决策表

先选择最简单且成立的切法，再考虑风格化转场：

| 实际变化 | 优先切法 | 使用条件 | 禁止 |
| --- | --- | --- | --- |
| 新语义、新主体、新视角 | `clean_cut`、`j_cut`、`l_cut` | 语义边界清楚，声音或画面能自然接续 | 为了“丝滑”在嘴型上溶解 |
| 同一动作延续 | `action_cut`、`match_cut` | 动作相位、方向和速度匹配 | 动作中途反向、重复或跳步 |
| 视线指向对象 | `eyeline_cut`、`cutaway` | 视线方向和对象位置成立 | 无对象的假视线切 |
| 固定机位删停顿 | 景别变化、短插镜、`j_cut`/`l_cut` | 新构图不裁头，声音连续 | 同景别硬跳或随机变焦 |
| 时间、地点或章节真实变化 | `dissolve`、`graphic_transition` | 有足够前后 handle，且变化确实需要被感知 | 模板擦除替代结构 |
| 运动方向或图形连续 | `directional_transition`、`whip_transition`、`match_cut` | 方向、速度、形状和落点一致 | 无方向依据的鞭甩 |
| 情绪由紧到松或由松到紧 | 干净切、声音桥、极短溶解 | 表演和声音已建立情绪关系 | 只靠转场制造不存在的情绪 |

每个切点必须填写 `transitionDecision`：`type`、`motivation`、
`continuityBasis`、`visualTreatment`、`audioTreatment`、`fallback` 和
`previewEvidence`。风格化转场还必须保留真实前后 handle；方向型转场要记录
`motionDirection`。先做干净切 A/B，复杂方案没有明显改善就使用干净切。

剪完停顿、口误或废句以后，必须从最终拼接时间线重新枚举全部真实连接点，
不能只检查方案中记得的几个效果切点。顶层 `connectionAudit` 记录检测方法、
连接点总数、逐项 ID、已检查数量、未解决项和正常速度证据；检测数量必须与
`cutSheet` 一致，未解决项非空时停止渲染。

可先生成连接候选：

```bash
node scripts/kacha.mjs connections CANDIDATE.mov \
  --cut-list final-cuts.json \
  --output connection-candidates.json
```

脚本合并编辑时间线切点与 FFmpeg 场景变化候选，并为每个点生成前后 handle。
像素扫描可能漏掉低差异跳切，也可能把动效误判为剪点；它只用于防漏，不能
替代最终时间线边界或正常速度审片。若本机有 PySceneDetect，报告会记录其
可用性，快速运动较多时可再用 AdaptiveDetector 交叉检查。

连接处理优先级：

1. 语义、动作和口型连续时用干净切、J/L-cut 或声音桥；
2. 固定机位删段产生姿态跳变时，用可感知景别变化或准确插镜；
3. 章节、时间、空间或图形关系真实变化时才使用有 handle 的转场；
4. 双切点、2–4 帧残片或短暂姿态抖动必须删除、重选切点或用有方向依据的局部运动吸收；
5. 每个新增转场重新匹配音效功能和峰值，不能无声套模板，也不能所有连接共用一个 whoosh。

## 节奏与运动

`rhythmMap` 分别记录语音重音、呼吸、动作峰值、音乐乐句、SFX 落点和章节转换。剪点先服从语义和动作，音乐只强化已成立的切点。

## 画面呼吸

画面呼吸遵守“收紧—停稳—释放”，不等于全片持续缩放：

- 问题、判断或情绪靠近时可缓慢推近；
- 事实密集、字幕阅读、笑点落下后必须停稳；
- 反思、总结或章节结束时可缓慢拉远；
- 只有真实空间方向成立时才横移；
- 极短结论与口播重音同时成立时，才允许一次冲击后停稳。

默认运动覆盖不超过 55%，静止不少于 45%；每 10 秒不超过 1.5 个主运动
事件，相邻事件至少间隔 1.2 秒。缓慢推拉和横移不配音效；短促冲击的动作
和音效能量峰值必须对齐口播重音。详细合同见
`visual-breathing-caption-typography.md`。

速度渐变只用于动作过程、插镜、建立镜头或转场动能。真人口型、字幕阅读和事实证据默认不变速。运动统一记录方向、持续时间、缓动、超调、运动模糊和停稳，不使用无落点的持续漂移。

## 效果理论合同

每个效果必须记录：

1. `trigger`：为什么此刻需要；
2. `function`：信息、情绪、视角、连续性、注意力或安全；
3. `mechanism`：如何解决问题；
4. `beforeState / afterState / entryExit`；
5. `simplerAlternative`：更简单方案及未采用原因；
6. `failureCondition`；
7. `qcEvidence`。

最小充分原则：

- 干净切能解决，不上复杂转场；
- 一处字幕强调能解决，不叠加蒙版、推拉和重音效；
- 原画面能说清，不插无关素材；
- 同一时刻通常最多两个主动视觉技巧，且只有一个主要焦点。

常用机制：

- J/L-cut、声音桥：用听觉连续软化视觉切换；
- 动作切、视线切：用自然动作吸收跳切；
- 图形/运动匹配：通过形状、方向或速度连接镜头；
- 信息卡、图解：降低复杂信息的瞬时认知负担；
- 分屏、画中画：同时呈现有比较、因果或信任关系的信息源；
- 蒙版：处理安全、局部焦点或真实空间遮挡；
- 打字效果：只用于“文字正在形成”本身有意义的搜索、命令、消息、引语或题眼；
- SFX：给可见动作、文字落位和转折加事件标点；
- BGM：提供基调和跨镜头连续，不承担主要信息。
