# 人声、背景音乐、音效与最终混音

## 两阶段音频流程

音频拆成两个阶段：

1. `dialogue_preprocess`：先分离人声与非人声，再只处理通过验收的 dialogue stem；
2. `final_mix`：视觉时序冻结后再加入 BGM、SFX、闪避和母带。

这样可以避免转场、文字动画和插镜时序变化后重复整链处理人声。

## 人声分离：必须先于降噪和增强

原始音轨、相机机内声、来源不明的导出音轨或已经混有环境声/BGM 的音轨，默认先生成分离候选：

```bash
scripts/separate_dialogue.sh INPUT.wav SEPARATION_DIR
```

标准产物：

- `original_reference.wav`：对齐后的原始参考，只用于同响度 A/B 和回退；
- `dialogue_isolated.wav`：候选人声；
- `non_dialogue_residual.wav`：环境声、原有音乐及其他非人声候选残余；
- `separation-report.json`：引擎、模型、源文件哈希、时长/采样率/声道和验收状态。

处理顺序固定为：

1. 粗剪冻结并从同一时间线导出待处理音轨；
2. 能力探测确认真实源分离引擎可用；
3. 生成 `dialogue_isolated` 和 `non_dialogue_residual`；
4. 对原始参考与独立人声做同响度 A/B；
5. 检查 residual 中是否仍有清晰语音泄漏；
6. 通过后只把 `dialogue_isolated` 送入降噪、人声增强和最终混音，`non_dialogue_residual` 不混回成片；
7. 后期需要的 BGM 和 SFX 使用独立新 stem 重新加入。

“人声”包括实际讲话、语义相关的自然换气和有表达作用的笑声/叹气；风扇、空调、交通、房间底噪、原有 BGM、碰撞声和无关环境声属于待剔除内容。口水音、爆音和齿音属于人声局部缺陷，在分离后单独修复，不能依赖源分离模型误删。

源分离是有损推断，不因用户要求“剔除非人声”就跳过验收。以下任一情况直接拒绝候选并回退原始参考，再使用降噪或局部修复：

- 辅音、尾音、轻声或吞音明显缺失；
- 齿音发虚、声音呈金属/水下质感；
- 呼吸、停顿或混响出现抽吸和门限开合；
- 声纹、口型同步、声道或时长被破坏；
- residual 中仍存在可辨认的完整词句；
- 只使用 `dialoguenhance`、中心声道提取、EQ 或普通降噪，却把结果标为人声分离。

保留 residual 是为了复核和回退，不表示允许把它重新混回最终成片。确需保留现场氛围时，应从许可明确、没有语音泄漏的独立 ambience stem 重新建立，并在方案中说明；不得直接复用含噪 residual。

## 人声诊断

先提取并检查：

- 持续讲话；
- 静音或弱声；
- 齿音、送气音；
- 爆音、口水音；
- 轻声与结尾；
- 有 BGM 的参考段。

记录噪声底、频谱、综合响度、true peak、声道结构、采样率和编码。只凭全片 LUFS 不能决定是否降噪。

## 人声增强

```bash
scripts/enhance_voice.sh INPUT.wav OUTPUT.wav \
  --preset natural \
  --denoise light \
  --target-lufs -20.5 \
  --true-peak -3.5 \
  --channel-mode preserve
```

默认 `natural + light denoise`，但 A/B 出现金属声、抽吸声、辅音损失、齿音变形或呼吸断裂时必须减弱或关闭。

- `natural`：保留本人声纹；
- `warm`：轻微增加厚度；
- `clear`：同响度下减少低中频堆积并克制提升存在感，不等于简单抬高高频；
- `off/light/medium`：降噪强度；
- `arnndn` 只有提供来源可信、许可明确且经过 A/B 的模型时使用。

脚本默认保留源声道，不再无条件压成 mono 后复制为伪立体声。只有明确的 dialogue stem 交付要求才使用 `--channel-mode mono|stereo`。不得把完整 voice/BGM/SFX 母带交给人声增强脚本。

口水音和爆音优先局部修复，不对全片强行 `declick`。本地链路可向成熟产品的自然听感靠近，但不声称与未公开商业模型一键等价，也不承诺恢复原录音不存在的细节。

## 同响度 A/B

参考另一版本时先分离：

- 综合响度；
- 频谱平衡；
- 动态与峰均比；
- 声道结构；
- 采样率和编码；
- BGM 掩蔽关系。

候选和参考使用同源时间段，并把响度匹配到约 `±0.2 LU`。更响、单声道化或低码率柔化都不能被误判为更清澈。

已经降噪、去齿音或压缩的人声默认不重复整链处理。优先回到处理前 stem；如果只能使用已处理 stem，只修改有证据的问题节点。

## 人声动态与响度

压缩只修复技术问题，不能抹平自嘲、结论、章节转换、停顿后的落点和轻声收尾。

知识类成片可从以下范围开始校准：

- 常规版本：约 `-18 LUFS`，true peak 不高于 `-2 dBTP`；
- 用户要求平台适配后再低一点：约 `-20` 至 `-21 LUFS`，true peak 约 `-3` 至 `-5 dBTP`。

这些不是平台统一标准，最终使用手机扬声器和耳机实听。

## BGM

BGM 应能感知但不抢注意力：

- 连续口播中，人声通常比闪避后的 BGM 高约 12–18 dB，再按频谱和设备实听；
- 用户说“再低一点”时，以认可版本为基线，每轮只降低 BGM 约 0.5–1.0 dB；
- 同时冻结人声、SFX、sidechain 和母带；
- 禁止降低整片音量冒充 BGM 变小；
- 入场、章节换挡和结尾服从音乐乐句，不为对拍切断语义。

## SFX

音效只强化已命名的动作、文字落位、转场或叙事落点：

- 用户点名本地音效时，读取 `references/sfx-library.md`，按 title、asset ID 和 SHA-256 精确命中；
- 打字效果的每个键音绑定字符实际落位帧，不能把一段连续键盘声铺在整句话下；
- “相似”“差不多”的音效不是可接受替代；精确素材不可用时宁可不加并报告；

- 低于人声，但最终成片中必须真实可感知；
- 与动作/文字误差通常不超过 1–2 帧；
- 必要时短暂闪避 BGM；
- 每个语义节拍通常只有一个主要声音事件；
- 不连续轰炸，不用大音量制造重要感。

整支视频不能把“统一风格”误解为“所有地方使用同一个音效”。冻结视觉时序后建立顶层 `sfxPlan`：

- `palette` 按功能至少区分文字/UI 落位、转场/运动、结论/情绪等类别；
- `events` 逐项记录时间、效果引用、asset ID、title、category、purpose、同步目标和相对人声音量；
- 4 个及以上事件至少使用 3 个不同音效，单个音效占比不超过 50%；
- 同一音效不得连续出现超过两次；逐字打字、连续列表等同一动作的节奏例外必须记录 `patternException`；
- 同一声音可以通过裁切不同段、轻微增益和空间处理形成变化，但不能把同一源文件重命名后冒充不同音效；
- 多样性服从功能，不为凑数量乱加声音；没有合适音效时保持安静。

最终 QC 同时检查“是否听得见”和“是否听起来都一样”。若多个转场、弹窗、文字落位使用同一音色且没有动作理由，退回重新选音。

## 最终混音 QC

至少保留或临时导出 `voice`、`bgm`、`sfx` 三类 stem，并检查：

- `original_reference / dialogue_isolated / non_dialogue_residual` 齐全，分离引擎和 A/B 结论可追溯；
- 最终 `voice` 来自已批准的 `dialogue_isolated`，非人声 residual 没有进入母带；
- residual 抽听无可辨认完整词句，人声 stem 无吞字、金属声、抽吸或呼吸断裂；
- 各 stem 响度和 true peak；
- sidechain 是否过度压制；
- BGM 进入、退出和章节换挡；
- 每个 SFX 落点；
- 开头、持续口播、轻声、章节转换和结尾；
- 手机扬声器与耳机。

最终视频保持 48 kHz 音频链路，不能无理由降到 44.1 kHz 或降低 AAC 码率。

## MiniMax 音乐网络策略

需要 MiniMax 音乐时默认中国区无代理直连：

- 清除大小写 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`；
- 设置 `NO_PROXY=*`；
- 授权、额度、生成和下载使用同一路由；
- 先预检，再发起付费调用；
- 提交后网络失败先查任务状态，状态不明不得自动重提；
- `music-2.6` 可请求 44.1 kHz WAV，下载后本地转为 48 kHz；
- 记录模型、参数、prompt 哈希、路由、任务 ID、调用次数和计费不确定性。
