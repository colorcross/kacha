# MiniMax 背景音乐默认入口与音效回退

本合同用于 Agent 为剪辑生成 BGM，以及现有音效库无法满足的明确 SFX。
**背景音乐默认从 MiniMax 音频网页版生成**：<https://www.minimax.cn/audio>，复用用户已有登录会话。
网页确实不可用且原尝试状态已查明时，依次考虑 MiniMax Design、mmx。
SFX 仍先用本地库；缺失音效保留 mmx → 网页 → 桌面的能力回退，不把音色设计当音效。
含音频的视频默认使用 MiniMax Design，见 `references/generated-media-assets.md`；
机器可读默认值为 `config/generation-routing.json`。最新明确需求可覆盖默认值。
这是 Agent 的工具选择和恢复流程；不是后台渲染器的自动浏览器任务，也不扩展到
视频、语音克隆、人物素材上传等其他业务。

用 `prepare --task local_optimization --stage visual_audio --modules audio_generation`
获取精简执行包；`rules query --stage visual_audio --modules audio_generation` 可检索
恢复决策。以上命令均经 `node scripts/kacha.mjs` 调用，不会自行提交生成。

## 生成前

1. 先检查项目现有 BGM/生成缓存与音效库。SFX 遵守 `references/sfx-library.md`
   及项目指定的 manifest、profile、试听索引；已有音效能准确匹配时直接复用。
2. 记录素材用途、叙事触发、目标时长、提示词、需要的版本数及既有授权预算。
   BGM 保留段落功能、编配与留白；SFX 说明动作、质感、落点，不能靠生成堆装饰。
3. 为同一需求建立稳定的逻辑素材 ID，在项目私有生成记录中关联各渠道尝试。
   切换渠道不重置次数或费用预算，不把未知费用记为零；凭据不进入记录。

## SFX / 显式 CLI 备用：mmx

读取当前可用 mmx skill，并检查本机 `mmx --version` 和对应音频命令的 `--help`。
模型、地区、参数、格式以当前能力为准；不得编造通用音效子命令，也不得把
语音中的音效标签当作独立 SFX 生成能力。网络细则见 `references/audio.md`。

| 情况 | 下一步 |
| --- | --- |
| CLI 缺失、所需音频能力未提供，或明确在提交前失败 | 记录原因，转网页版 |
| 参数错误 | 先按帮助修正并本地预检；仍无法执行则转网页版 |
| 明确的服务失败，已确认没有生成中的任务或可用结果 | 在既有授权预算内转网页版 |
| 超时、断线、空响应，无法确认是否已受理 | 先查 CLI 状态或对应账号的任务/生成历史；不立即再次生成 |
| 已生成但下载失败 | 找回该结果并重试下载，可通过网页或桌面取回；不重新生成 |
| 额度、订阅或审核限制 | 查清限制是否也适用于下一渠道；不自动购买、充值或绕过审核 |

任务状态未知时可以打开下一渠道查询，但**不能把打开网页当作重新提交的许可**。
不同渠道的账号、任务历史或额度未必互通；看不到记录不等于原任务不存在。
只有确认原任务未受理、已明确失败/取消，或用户明确接受未知结果下的新尝试成本后，
才可再次提交。同一限制下不循环换渠道。

“任务失败/取消”只说明生成状态，不证明未扣费或退款；费用仍须单独对账。
禁止在返回码非零、页面空白或本地无文件时直接记为“未提交”。

## BGM 默认：已登录浏览器的 MiniMax 音频网页版

入口：<https://www.minimax.cn/audio>。用户已说明默认浏览器登录了账号；执行时
复用该浏览器的现有用户会话，优先定位已有标签页，否则在同一浏览器打开入口。
不要新建临时浏览器配置而丢失登录态，也不要读取或导出 Cookie、密码和令牌。

- 使用可用的浏览器/计算机操作工具读取当前界面，再选择音乐或音效功能。
  登录、功能、额度、价格和下载能力须在当次使用时确认，不根据旧截图猜按钮。
- 先检查既有任务和生成历史，再在需要时填写提示词、时长等实际支持的参数。
  沿用逻辑素材 ID、已批准需求与预算；同一获授权生成动作仅更换渠道，无需重复确认。
- 发起一次后记录可见任务标识，等待/查询状态；页面卡顿或按钮反馈不明时不连点。
  界面无任务 ID 时记录可定位的标题、时间与结果信息，不伪造 ID。
- 成功后下载原始音频到项目私有素材目录，校验文件并试听；网页显示成功不等于已交付。
- 页面不可达、无法恢复登录、所需功能缺失或生成/下载持续不可用时，记录具体原因，
  再转桌面版。若已有任务结果未知，桌面版也只能先查询/找回，不能直接重复生成。

浏览器连接器异常时，先检查是否可用原生浏览器界面操作同一已登录会话；
连接器错误不是产品网页不可用的证据。仍无法访问时据实记录，再尝试桌面版。
登录或验证码仅在实际阻塞且桌面版也不能完成时请用户处理，不绕过验证。
首页可能默认是语音合成；BGM 必须进入音乐创作并选择纯音乐/无歌词模式。
“音色设计”创建人声音色，不等于独立环境/动作音效生成；没有所需 SFX 功能就
继续下一渠道，不把 TTS、歌曲或音色设计当作缺失音效的替代。

## BGM 网页不可用时：本机 MiniMax Design

使用已安装的 **MiniMax Design**，macOS 常见安装位置为
`/Applications/MiniMax Design.app`。先定位应用并读取真实界面，核实登录态和当前
音乐/音效能力，再按同一需求执行查询、生成或下载。不假设桌面版拥有网页版的全部能力。
检查并保留当前输入草稿、选中模型及在途任务；需要新生成时使用独立创作页，
不覆盖其他任务的输入，也不顺便重启升级应用。明确只生成本次音频，不让通用
Agent 扩展成视频、海报或多版本整套制作；若其音乐工具最终调用同一故障后端，
记录同源故障，不继续绕圈。

桌面版表示客户端在本机，**不代表音频由本地模型离线生成，也不代表免费**。
预算、上传授权、状态不明不重提以及下载验收规则与网页版相同。
若桌面版也不可用，可在已有授权范围内检查 mmx 备用能力；均不可用时报告具体失败环节并保留工程与任务记录。可选声音仅按已允许的
回退省略，必需声音保留为待完成项，不伪称生成成功。

## 结果接回剪辑

- 私有生成记录保留逻辑素材 ID、用途、提示词哈希、尝试时间、失败原因、
  `provider=minimax`、实际渠道 `mmx|web|desktop`、可见任务/结果标识、费用状态与许可依据。
  模型或费用界面不可见时明确记为未知，不推断为某一模型或零费用。
- 原始下载文件计算 SHA-256，检查可解码、实际时长、声道与采样率，排除空文件、
  截断和误下载网页。原件只读，另建 48 kHz 工作副本并记录其 SHA。
- 试听确认 BGM 的段落/人声保护，以及 SFX 的语义、攻击峰值和尾音；文件生成成功
  不等于剪辑效果合格。仍按 `references/audio.md` 的混音与成片 QC 执行。
- SFX 通过 `sfx import` 的显式 mapping 进入项目库，保留来源和授权。
  私有音频、账号/任务记录及无公开再分发权的素材不得进入公共仓库、Release 或安装包。
- 新的付费承诺、超出已有预算或未经授权的源素材上传才需要补充授权；
  不因渠道切换对已经授权的相同操作反复询问。

### 与现有费用台账和音效导入器接通

实际金额以项目 `.kacha/cost-ledger.json` 为准，素材生成记录引用它的 entry ID，
不另建一套互不对账的金额合计。每次货币计费提交前依次执行 `cost reserve`、必要的
`cost approve`、`cost consume`；consume 使用同一 provider/capability、唯一
execution ID 和本次意图 SHA，成功占用后才点击生成。重复 consume 会被阻断。
consume 是防重复占用，不证明远端已受理；中断后保留 `reconciliation_required`，
先查远端。用真实账单 `cost reconcile`，确认退款再 `cost refund`；新尝试用新 entry
并关联同一逻辑素材 ID，不覆盖旧记录。只查询和重新下载已有结果不创建生成尝试。

网页/桌面的声贝、积分、订阅额度与 CLI 货币成本不能直接相加，也不能假定互通。
另记渠道、计量单位、扣减数量和账单依据；只有有可核实换算依据时才录入货币实际额。
明确包含在已批准订阅/免费额度内的使用记录单位消耗，不凭空声明订阅成本为零；
当前货币台账不能表达的费用保持未知，在已有额度/次数授权内操作，不伪造换算价格。

`sfx import` 的 mapping 每项可带 `provenance` 对象，必须包含 `provider`、
`transport`（`mmx|web|desktop`）、`logicalAssetId` 和 `promptSha256`，并可附
任务/结果标识、费用 entry ID 与许可证据引用。导入器将其保留在私有 manifest，
同时记录原件与 48 kHz 工作副本的 SHA；未记录公开许可时仍为项目私有。
重复导入如来源记录不一致会阻断，不能把已有来源悄悄覆盖。来源存在不等于许可获批。

全局 skill 更新对新任务生效；已冻结工程保留运行包身份，按已有运行更新入口采用
新合同，不直接改写旧运行包或工程产物。
