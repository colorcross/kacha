# 视觉效果设计预检与 Figma 条件路径

信息卡、流程图、弹窗、风格化转场、人物后文字以及人物/局部/隐私等蒙版效果，必须先设计、后实施。设计预检解决的是“做成什么样、为什么这样动、听起来是什么感觉”，不能用渲染后的成片反向冒充设计。

开始设计前先解析项目视频设计系统。`implementationHandoff` 必须记录
`designSystemId`、`designSystemVersion`、`designDigest`、`sceneId`、
`componentIds`、五组 `modeSelection` 和实际使用的 token 路径；单个模块只记录必要偏差，
不得复制整套字体、颜色、圆角、阴影和缓动参数。无批准偏差时，渲染器直接
消费解析后的统一令牌。

## 必须提交的设计包

每个高影响视觉效果在 `edit-plan.json` 中提供 `designPreflight`：

- `designSystemId`、`designSystemVersion` 与 64 位 `designDigest`；
- `sceneId` 与非空 `componentIds`；
- `modeSelection`：`show`、`aspectRatio`、`language`、`surface`、`density`；
- `status=approved_for_implementation`；
- `artifactMode`：`local_styleframe` 或 `figma`；
- `artifactRef`：本地样式帧、设计稿或交接文件；
- `artifactSha256`：实际样式帧的 SHA-256；
- `implementationManifestRef` 与 `implementationManifestSha256`：由
  `design render` 生成的实施清单及其摘要；
- `layoutSpec`：画幅、人物/头像、字幕、品牌、平台 UI 和模块边界；
- `motionSpec`：进入、停稳、退出、持续时间、缓动、方向、层级和 motion blur；
- `soundSpec`：声音功能、候选类别、峰值落点、相对人声音量及 BGM 闪避；
- `stateFrames`：至少包含进入、信息最满/停稳、退出三种状态；
- `implementationHandoff`：五类解析后字体、字体选择摘要、真实 token 路径、
  尺寸、归一化坐标、帧数和资产映射；
- `qcEvidence`：手机尺寸样式帧、亮/暗背景、人物安全区和短动效预览。

设计稿通过不等于实现通过。正式实现后仍需对照设计稿检查构图、时序、音效落点、边缘和退出状态。

样式帧是“峰值状态”证据，不是可直接贴进时间线的最终素材。横版和竖版必须
分别交付峰值帧，并在实施清单里为每种画幅记录 `entry / hold / exit / sfx`。
正式渲染时必须把这四段合同转换为关键帧、遮罩层级和音频事件；不得只把峰值帧
静态显示数秒。验收至少包含一段正常速度预览，检查：

- 进入动作是否与口播或画面动作同拍，而非统一提前；
- 停稳时间是否足以读完，但没有拖慢节奏；
- 退出是否在切回真人主画面或下一字幕前完成；
- 音效是否只强化动作峰值，并为人声和 BGM 留出空间；
- 横竖版是否各自保持人物、字幕、平台 UI 和重点信息安全区。

本地设计包建议直接生成：

```bash
node scripts/kacha.mjs design render \
  --scene SCENE_ID \
  --output design/SCENE_ID/styleframe.svg \
  --manifest design/SCENE_ID/styleframe.manifest.json
```

验证器会读取真实文件并核对 hash、当前 design digest、场景、组件和字体选择。
仅填写看似正确的文件名或摘要不能通过。

## 本地样式帧还是 Figma

默认使用最短可验证路径：

- 单一画幅、单个模块、状态简单：使用本地 PNG/SVG 样式帧和 JSON 动效参数；
- 多状态流程、可复用组件、多画幅适配、复杂图表或品牌级视觉系统：优先使用 Figma；
- Figma 服务不可用、没有授权文件或隐私素材不能上传：回退本地样式帧，不得跳过设计预检。

Figma 是条件设计后端，不是渲染引擎，也不是每个效果的强制依赖。只有它能明显降低布局、组件复用或多画幅交接风险时才启用。

## Figma 工作流

使用 Figma 时：

1. 先读取当前 Figma 文件、页面、组件、变量、字体和命名约定；
2. 不把未授权原片、人物照片或私密截图上传到新文件；必要时用经过授权的代表帧或占位形状；
3. 为每个效果建立 `entry / peak / exit` 样式帧；流程图还要有关键中间节点状态；
4. 把人物头像、字幕、品牌和平台 UI 安全区作为可见辅助层；
5. 检查真实字体是否可用，不猜字体名或字重；
6. 设计完成后记录 `figmaFileUrl`、`figmaNodeIds`、导出证据和实现参数；
7. 用截图核验裁切、重叠、文字溢出、层级和多画幅变化，再交给时间线实现。

Figma 设计必须可回到具体 node ID。只写“在 Figma 里设计过”或只提供文件首页链接，不算有效交接。

## 各模块的设计重点

### 信息卡、流程图、弹窗

- 先决定全屏替换还是人物安全布局；
- 信息最满状态仍需保持呼吸感；
- 流程节点随口播逐步建立；
- 阴影、箭头、弹窗尾巴和装饰也计入碰撞边界；
- 为每个节点定义出现音、完成音或无音策略。

流程图必须先选择视觉变体：

- **空间光路**：技术、AI、工具与空间关系明显的流程；底图必须与浅暖轻浮层使用同一张原实拍，使用局部径向景深场、深中性透明玻璃节点、蓝色曲线路径、局部橙红结论路径和克制粒子；禁止矩形黑块、全屏暗罩和大面积白卡。
- **浅暖轻浮层**：知识、方法、清单与亲和叙述；使用透明暖白小卡，背景必须
  轻微透出，同一时刻最多三张卡完整可读；继承已批准高保真样板的非对称编辑版式、头部负空间、双层 PIP 边框和逐项建立逻辑。
- **幽默漫画**：真实反差、误会、预期落差、尺度错位、反应与回扣；保留人物和事实证据，用局部分格、墨线、克制网点、反应裁切和不超过 12 个汉字的气泡强化笑点。每个语义拍最多一个 punchline，禁止儿童卡通化、表情包墙、罐头笑声和无触发抖动。
- **像素风**：AI、工具、规则、计数、状态变化与可量化流程；人物、证据和文字保持清晰，只对图形层使用 6–12 px 基础网格、最多 8 个强调色、整数硬边和每步 2–4 帧的量化运动。禁止全屏低清、持续扫描线、无叙事故障和泛游戏 HUD。
- **暗黑科技风**：异常、风险、冲突证据、隐性机制、真伪判断或系统边界；保持真人和证据正常曝光，只用局部观察孔、至多两层证据和一个裁决区建立张力。普通说明不启用取证拓扑，禁止整屏黑化、通用 HUD、数据雨、扫描线和随机 glitch。

五种变体均允许按真实画面调整节点数、路径、位置、尺度、透明度、节奏和音效，
但必须遵守其 `motionContract` 中的 invariants。若人物或字幕安全区无法满足，
必须缩减节点、改变布局或回退，不得为了“还原参考图”遮住人物。

效果身份高于风格表现：组件、布局、渲染器和动效参考图必须先兑现注册效果本身的
功能拓扑，禁止为了强化风格把折线图改成瞄准镜、把画中画改成流程图、把干净切改成
证据卡。只有列入风格白名单的场景级效果可以替换为完整叙事拓扑；其他效果只允许
改变材质、边缘、色彩和受控运动参数，并在 `renderPlan` 中记录实际渲染器与视觉原型。

多状态流程图、清理清单和逐项点亮模块必须使用“持久底图 + 局部状态更新”：

- 底色、标题、未激活节点和全局装饰在模块有效区间内保持像素稳定；
- 只允许当前节点或其连线在局部区域内改变亮度、颜色、描边或完成状态；
- 节点之间不得让整张全屏 PNG 重复淡入淡出，也不得用全屏闪白表示完成；
- 计划用 `progressiveStateSpec` 记录 `persistentBase=true`、
  `updateMode=local_highlight|local_reveal`、各节点 `activeRegionBounds`、
  `screenFlashPolicy=forbid_full_frame_fade` 和 `stateBoundaryQC`；
- 每个状态边界抽取切换前后各 2 帧做差分：活动区域外不应出现可见亮度跳变；
- 若渲染器只能整帧替换，必须关闭状态间 alpha fade，并确保所有非活动像素完全一致。

### 风格化转场

- 先验证时间、空间、动作、方向、图形、声音或情绪连续性；
- 设计前后真实 handle、运动方向、峰值、模糊和停稳；
- 同时提供干净切 A/B；复杂转场没有明显改善就回退；
- 音效必须匹配运动形态，不能把同一个 whoosh 套在所有转场上。

当口播明确进入“转场演示”场景时，可在注册表内选择更强的
`iris_reveal`、`radial_clock`、`focus_blur` 或 `zoom_punch`，但仍需保留
真实 handle、干净切 A/B 和匹配音效。所谓“酷炫”应来自明确的空间/焦点/尺度
变化，不得退化成整屏色块横扫或无依据闪白。

### 人物后文字

- 先确定字体、字号层级、语义分组、位置、色值、对比度和可见面积；
- 默认只使用 2–4 个汉字的核心词，最长不超过 7 个汉字；长句改用头顶标题、字幕或信息卡；
- 竖版优先置于头顶上方并保留呼吸距离，只有短词允许与发丝轻微重叠形成视差；
- 两字分置人物左右时，字间净空至少接近头部宽度，每个字至少保留 85% 可读面积，不能让头部同时挡住两个字的字心；
- 样式帧必须包含真实人物蒙版或可靠占位轮廓；
- 动效按短语分批建立，声音跟随最终落位而不是随意铺满；
- 头发、眼镜、手部或快速运动边缘不稳时回退信息卡/字幕强调。

### 其他蒙版

- 明确蒙版用途：人物分层、局部提亮、隐私保护、文字遮挡、分屏或转场；
- 设计羽化、扩张/收缩、跟踪对象、边缘容差和失败回退；
- 隐私蒙版以不可识别为第一目标，不能为了“高级感”减弱保护；
- 局部提亮或美化要检查肤色、边缘和背景是否被误处理。

## 失败条件

以下任一情况不得进入实施：

- 缺少进入、信息最满/停稳或退出状态；
- 没有真实字体、色值、尺寸、坐标或动效帧数；
- 音效只写“加一个合适的声音”；
- 设计稿遮挡人物头像、字幕、品牌或平台 UI；
- Figma 链接没有 node ID、导出证据或实现交接；
- 实施无法复现设计稿，且没有记录偏差和重新批准。
