# 字幕、封面、品牌与系列层

## 字幕依据与校准

最终时间线音频决定时间、实际说法、停顿和语气。原始文稿只用于校准专名、数字、术语、标点、吞音和上下文，不能静默覆盖真实发音。

流程：

1. 从最终音频重新转写；
2. 对照原稿和项目词表提出候选修正；
3. 复听数字、年份、单位、书名、人名、否定、条件、因果和结论；
4. 不确定项标记时间码并人工确认；
5. 保存重要修正的 `subtitleCorrectionLog`；
6. 正常速度通看最终烧录结果。

不能只把字幕改“正确”而让声音保留事实性口误。此时应重剪、补录、画面更正或忠实保留。

## 单行短视频字幕

9:16 口播默认：

- 每种语言单行；
- 不自动折行，不写强制换行；
- 无背景色、无底板；
- 超宽时按语义拆成连续字幕卡；
- 字幕位置主动上移，1080×1920 可从画面高度约 68%–72% 开始校准；
- 真实字体测宽，文字和阴影都不能越过安全边；
- 动词与宾语、数字与单位、否定结构、书名、固定搭配和比较项不能拆坏。

中文单卡可从约 8–14 个汉字开始，但字数不是验收标准。最终以真实渲染宽度、语义和阅读时间为准。

## 创作者字幕 profile

仅在项目显式启用相应创作者 profile 时使用。字体必须来自项目授权注册表。“浅暖轻浮层”“空间光路”“幽默漫画”和“像素风”的主字幕固定使用真实金陵体，不配置宋体、楷体、漫画字、点阵字或系统字体 fallback；缺字或文件变化直接阻断。

- `fontWeight=400`，不加粗、不描边；
- 无底板；
- 黑色柔和阴影固定 60% 不透明度；只能调整模糊和偏移适应局部背景，不能变成硬描边。

字幕 profile 可以被项目元数据覆盖，不能被 Skill 强制应用到其他品牌。

## 双语字幕

用户明确需要时才启用。英文在上、中文在下时：

- 英文和中文各自保持单行；
- 两种语言按各自语法断句，不逐词机械对齐；
- 主语言承担阅读主线，辅助语言降低一级；
- 英文字号需要在手机尺寸清晰，不能为了双语整体缩得过小；
- 同一语义卡的入退点一致，但允许不同语言文字长度不同；
- 任何一行超宽都先重切语义卡。

## 明暗底适配

至少定义两个受控变体：

- `darkSurface`：暖白主字、暖金强调和柔和深色阴影；
- `lightSurface`：炭黑/深褐主字和深琥珀强调。

只切换颜色和阴影，不改变字体、字号、字重、基线和断句。亮暖信息卡上不能继续使用白字。每个变体至少检查一张 100% 原尺寸帧和一张手机缩略帧。

## 逻辑重音

强调跟随逻辑，不只跟随音量：

- 核心判断、结论和章节题眼；
- 否定、限制条件、因果和转折；
- 关键数字、时间、专名和行动指令；
- 铺垫后的落点或笑点。

同一字幕卡通常只有一个主强调点。默认字幕不允许临时加粗或描边时，使用强调色、轻微缩放、字距、下划线、标记或音效。

SFX 与文字动作一致：tick/click 对应落位，下划线对应书写，数字/结论可用克制 tonal hit，有空间位移时才用 whoosh。入点误差不超过 1–2 帧。

## 打字效果

只用于搜索词、命令、消息、引语形成、章节问题或题眼。先锁文案，再制作动效。

- 中文可从约 6–12 字/秒起调；
- 英文可从约 10–18 字符/秒起调；
- 按语义短语揭示，不必机械逐字；
- 标点处轻停；
- 对应语音结束前约 0.1–0.3 秒完成；
- 打字声低于人声并削弱尖锐高频；
- 检查漏字、重字、缺字、字体 fallback 和 seek 后错位。

## 口播字幕的信息关系

普通口播默认使用单行主字幕。只有信息关系明确时才升级排版：

- 左右：对照、并列、前后变化；
- 上下：标题与补充、问题与回答；
- 前后：人物和观点形成真实空间层次，且已经有逐帧人物蒙版。

同一时刻最多三个阅读区和一个主重音。普通字幕不加音效；逻辑重音、信息组
首次落位或前后景大字主峰才允许一次功能明确的 SFX。字体必须先通过本地
注册表按场景角色、字符覆盖和项目授权解析。具体布局、字体角色、命令和 QC
见 `visual-breathing-caption-typography.md`。

## 封面合同

视频和封面是两套画幅合同。创作者短视频可从以下规格开始：

- 竖版封面 `3:4`，高质量 2160×2880；
- 横版封面 `4:3`，高质量 2880×2160；
- 横版继承已批准竖版的色板、字体、人物处理、光线和材质，但重新排版；
- 禁止把 9:16 视频首帧直接作为正式封面；
- 禁止拉伸或机械中心裁切；
- 不生成独立 3 秒封面视频。

默认风格明亮、温暖、克制。人物优先抠出或放进独立照片模块，不直接铺满背景；
默认人物高度约 38%–44%，允许范围约 32%–48%，宽度通常约 22%–30%。
人物是信任锚点，不是背景；必须给标题和内容证据留下连续负空间，并保留头顶、
脸、眼镜、下巴、肩部和必要手势。

标题、人物、品牌、系列名和装饰线分别使用安全框，基础内边距约为画面 6%–8%。手机缩略图不可读、文字相互覆盖、人物头部被挡或越界都直接失败。

标题使用项目指定且授权可用的字体；fallback 可用系统自带的 `Lantinghei SC Heavy`、`Hiragino Sans GB W6`、`Heiti SC Medium`。必须实际渲染确认，不能静默回退。

封面普通大面积使用暖灰和中性色；品牌使用暖橙，核心冲突可用珊瑚色，AI/系统
概念可用理性蓝，完成/证据成立可用验证绿。渐变只能承担一个主焦点，不覆盖
整块普通背景或所有标题。

“行者大灰”动漫封面在原有暖灰、米白、炭灰基础上固定增加四个语义色：暖橙、珊瑚红、理性蓝和验证绿。四色必须分别承担品牌、冲突、AI/系统、完成/证据成立的功能，不作为等权彩虹装饰同时铺满画面。

### 动漫幽默叙事封面

项目明确启用时，封面以“动漫人格锚点 + 主题关系 + 核心标题”为默认结构。
这不是人物、道具和大字的机械并置；画面必须能说清“人正在遇到什么任务、冲突、
结果或证据”。

- 动漫人物只使用项目批准的身份参考，稳定保留黑框眼镜、短刺发、成年脸型特征和运动造型；运动服以深藏蓝为主，运动鞋使用灰白基础色并允许少量当期语义色点缀。封面不强制全身或露鞋，按标题负空间和人物比例选择半身、三分之二身或全身；运动鞋进入画面时不得出现品牌 Logo。每期根据选题重新设计动作与表情。大头比例、夸张惊讶或尖叫表情不是禁区，可在确实服务于标题冲突、动作关系和缩略图识别时使用；强度由选题决定，不机械套用。风格可以从成熟编辑插画到高质量漫画喜剧变化，但拒绝与主题无关的廉价贴纸堆砌。
- 人物必须产出独立抠图层并融入主题场景，允许主题元素出现在人物前后景以建立空间关系；禁止使用矩形原照、照片卡、相框或全景原照代替人物抠图。
- 主题元素只保留一组主关系，与标题和内容证据一致；无关食物、装饰、烟雾和“热闹填充物”应删除。
- 默认先由 Codex 生成或组合无字场景，再使用已验证的真实字体确定性排版；图像模型不直接生成正式中文标题。
- 项目指定封神榜书时，它只承担主标题；栏目、期号、系列和辅助信息只使用项目授权细体。
- 3:4 与 4:3 分别构图，不用同一张场景机械裁切。手机缩略图中主标题、人脸和主题关系仍必须可读。
- 生成服务失败时可用真实批准照片生成本地合成候选，但必须标记为降级，不与正式动漫风格混用。

#### 院线级 3D 动画人物语言

“皮克斯风格”只作为用户口语输入，不作为复制具体工作室或角色的许可。生产
系统统一将其解析为原创的高品质院线级 3D 动画电影人物：温暖、圆润但不
幼龄化，动作和表情可按叙事夸张；皮肤、发束、眼镜与布料使用精细材质，
采用电影级柔暖主光、轮廓光和可信体积关系。必须保留大灰本人可识别的成年
脸型、真实年龄感、黑框矩形眼镜、短刺黑发和深藏蓝运动服。

不得复制或近似 Pixar、Disney 或其他现成角色、影片人物比例、服装、发型、
场景、Logo、商标或 IP。不得把具体角色作为脸型或表演模板。3D 只升级人物
造型与光影，不替换封面的语义编辑结构：背景仍使用同一主关系下三至五个
场景碎片、前中后景、至少两层遮挡、尺度反差、纸张/油墨/网点和印刷质感；
至少一个主题元素在人物前景、一个在人物后景。单人物居中、背景虚化、大字
压顶的普通 3D 动画海报直接失败。

### 五栏目差异合同

同一创作者的栏目不能只通过更换栏目名区分。项目 profile 必须把共同身份锚点、
字体、色板、画幅和证据边界放入母合同，再为每个正式栏目提供独立的
`narrativeRelation`、`titleStrategy`、`person`、`topicElements`、
`colorPriority` 和 `composition`。栏目名与 `第N期` 是所有正式封面的硬门禁。

“行者大灰”当前五栏目按以下关系解析：

- 工具分享：问题或费劲状态 → 工具介入 → 可验证结果。真实界面、输出和前后
  对比优先；暖橙负责品牌，理性蓝负责系统，验证绿负责结果。
- 解读好书：问题或矛盾 → 阅读与思考 → 洞见或现实检验。书名和作者降为辅助，
  五栏目中留白最多；珊瑚红只用于真正的矛盾。
- 有限的无限游戏：行动目标 → 现实阻力或选择 → 结果偏差与下一步。动作关系最强，
  真实事件、路线、时间、装备和结果证据优先；运动鞋可不出现，出现时不得有 Logo。
- 灰常AI：人的目标与判断 → AI 系统运行 → 冲突、验证或协作结果。允许与真实冲突
  匹配的夸张惊讶、崩溃或尖叫表情；理性蓝建立系统，珊瑚红建立冲突，验证绿只给
  检查通过或结果成立。
- 闲聊：具体触发或困惑 → 拆开聊 → 暂定判断或开放问题。人物亲近、直接、松弛
  但不轻浮；主题元素控制在 2–4 个同一关系碎片，暂定判断不得使用验证绿冒充结论。

五栏目都使用上述同一院线级 3D 人物身份，但不得复用同一姿势：工具分享偏
明亮精确和任务推进；解读好书偏柔暖沉静和思考重量；有限的无限游戏强调
身体重量、运动惯性和真实环境；灰常AI使用理性蓝系统光与暖色人物主光，允许
最鲜活的反应与叫停动作；闲聊使用明亮柔和的真实工作空间光线和成年交流动作。
栏目差异只能改变表演、镜头和灯光侧重，不能改变
大灰身份锚点、服装或高密度语义拼贴母结构。

栏目差异不得改变共同身份：黑框矩形眼镜、黑色短刺发、成年可识别脸型、深藏蓝
运动服始终锁定。动作、表情和景别随话题变化；服装不变，也不强制全身或露鞋。
人物必须是透明独立图层并融入主题前中后景，不得恢复矩形照片模块。

## 品牌 profile

品牌是项目配置，不是不可覆盖的 Skill 常量：

- `brand.enabled=false` 时不显示；
- `brand.name` 必须由项目设置，不提供作者专属默认值；
- `seriesTitle` 仅在当前系列存在时显示；
- 品牌显示区间由项目指定，可全片、章节或片尾，不强制所有视频首帧到末帧；
- 同一时刻只有一套品牌模块；
- 插镜、图解和信息卡不得重复嵌入品牌；
- 模块避开人物、字幕、来源和平台 UI；
- 亮底、暗底分别使用可读变体。

当项目要求全片常驻时，`brand_bug`、`show_label`、`issue_badge` 和
`series_marker` 必须持续存在，但使用细体、局部自适应微玻璃或阴影，透明度保持在
62%–80%，对比度不低于 3:1，显著度不高于主标题的 32%。局部背景变化时只改文字颜色、阴影或微型衬底，不能用高饱和色块强行保证可读。

创作者 profile 应使用稳定识别字体、克制字距和低一级系列名；弱化横线细、短、低对比，不成为第二焦点。

## 系列身份门禁

不能只因为作品“看起来像同一类”就擅自添加系列名。inventory 阶段按以下证据判断：

- 用户明确说明；
- 当前项目目录或项目 manifest 的系列字段；
- 已批准的同系列封面、成片或品牌规范；
- 稳定重复的系列标题，而不是单期标题中的偶然词语。

`seriesIdentity.status=detected` 时：

- `seriesTitle` 必须唯一并使用已批准写法；
- 视频与封面都必须出现系列标识，禁止只改封面或只改视频；
- 两处使用相同识别字体、字距、色彩逻辑和层级，但按各自画幅重新排版；
- 视频标识记录显示区间，封面标识使用独立安全框；
- 至少检查视频开头、中段、信息模块、结尾，以及所有封面画幅；
- 标识避开人物头脸、字幕、来源、二维码和平台 UI。

无法判断时使用 `undetermined` 并停止在方案阶段；确认不是系列时设为 `not_series`，不得为了“统一感”临时创造系列名。

## 开头和结尾

短视频默认不插入独立静音封面段。需要首帧识别时，可让封面覆盖约 0.3–0.8 秒并淡出，但人声从 0.00 秒自然开始。

`contentEnd` 由最后一个有效音节和叙事落点决定。默认只保留最后音节后的 1–3 帧自然收束，不留无意静态尾巴、尾静音、冻帧或黑帧。
