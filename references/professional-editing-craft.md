# 专业剪辑：从段落模板到镜头、声音和执行

先回答观众在这一段需要理解什么，再决定用哪个镜头证明。段落模板负责叙事顺序，
十二种手法负责镜头组接，五套视觉语法负责包装语言。三者不能混成“某博主滤镜”。
参考依据与观察范围见 `docs/CREATOR_EDITING_RESEARCH_2026-09-12.md`。

## 入口与默认路由

```bash
node scripts/kacha.mjs templates recipes --recipe product-demo
node scripts/kacha.mjs intelligence director --cues cues.json \
  --show tool-share --recipe auto --output director-plan.json
node scripts/kacha.mjs intelligence validate-plan --plan director-plan.json
```

| 模板 | 叙事组织 | 适用与回退 |
| --- | --- | --- |
| `evidence-story` 实验与证据推进 | 问题 → 条件 → 尝试/失败 → 证据 → 有限定的结论 | 实验、测评、AI 边界；缺实测源时列缺口，不能用装饰素材代替 |
| `product-demo` AI 与工具操作演示 | 卡点/结果预览 → 输入 → 操作 → 反馈 → 对比 → 限制 | 工具分享和可复现演示；缺操作链就补录，不用假点击 |
| `field-journal` 沉浸式现场记录 | 地点/意图 → 行动 → 细节 → 反应 → 变化 → 反思 | 旅行、训练、真实事件；环境声不可用时保持干净剪接并记录缺口 |
| `reflective-talk` 观点与思考留白 | 问题 → 观点 → 文本/经历 → 反例 → 边界 → 收束 | 解读好书、闲聊；没有变化时保留讲述，不自动制造冲突 |

默认先数可靠 cues 中的显式信号；平局按栏目，仍平局按注册顺序。没有内容信号时
只给栏目默认，标记为待内容复核。`confidence < 0.65` 或 `low_confidence` 不能驱动
自动模板选择或高影响包装。显式 `--recipe` 优先；未知 ID 报错，不静默替换。

模板的 `sequence` 是检查提纲，不自动重排原素材。不能因为缺少“失败”就编造失败，
也不能为了结构完整切断真实时间关系。四模板的默认安静比例分别为 45%、45%、65%、
70%，是咔嚓可调整的设计起点，并非对三位博主的测量结果。

## 十二种专业手法

| 手法 | 先确认 | 实施重点与失败回退 |
| --- | --- | --- |
| 证据揭示 | 当前源、条件、可读结果 | 先条件再结果再判断；不能只用“研究表明”字幕充当证据 |
| 操作链 | 输入、动作、反馈、输出均有源 | 一次一个观察区；保留错误与修复；压缩等待要标记 |
| 同条件对比 | 同任务、版本/日期、尺度、单位和曝光 | 声音 AB 先同响度；一项差异一次强调；不只呈现有利样本 |
| 动作匹配切 | 同一动作相位、方向、速度 | 在动作中接近景/特写；有跳步或反向先换源段或干净切 |
| 地点桥接 | 新地点能被辨认、空间关系成立 | 建立 → 行动 → 细节；不能连续特写让人不知道在哪里 |
| 反应停顿 | 真实表情、停顿、恢复 | 不抢在观众反应前出包袱字幕；不强行加罐头笑声 |
| 现场声窗口 | 独立、可用、与画面同源的录音 | 让脚步、机械、风雨或动作成为前景；暂停 BGM/装饰 SFX |
| J-cut | 下一场真实音频 handle、无口型冲突 | 下一场声音先到，画面稍后到；只移动该剪口，不改全片同步 |
| L-cut | 上一场真实音频 handle、无口型冲突 | 当前声音延续到对应证据或反应；字幕仍跟最终音频 |
| 章节换挡 | 真实新问题、地点或论证层级 | 完成旧问题再开新问题；不是每隔固定秒数插片头 |
| 问题回收 | 开头问题确已回答 | 回到同一对象，展示结果及限制；失败结尾也成立 |
| 阅读停稳 | 实际可见文字、完整出现时刻 | 从完整落位后计时；读完前不换镜、不持续推拉 |

默认一个语义拍最多返回三个手法候选，保护阅读、反应和现场声优先；其余放到
`deferredTechniqueIds`，不能理解为同时执行全部候选。同一时刻仍只有一个主焦点。

## cues 如何携带真实依据

```json
{
  "id": "demo-result",
  "start": 12,
  "end": 18,
  "text": "这是刚才操作得到的结果，也包含一次失败。",
  "signals": ["screen_demo", "reading"],
  "confidence": 0.96,
  "craft": {
    "screenText": "第一次失败，修改参数后完成",
    "textReadyOffsetSeconds": 0.4,
    "evidence": ["input_visible", "operation_visible", "result_visible", "text_visible"]
  }
}
```

`evidence` 是制作者对当前素材的标注，不是模型已经看过画面的证明。标注前用当前
转写、帧或正常速度片段确认；注册表逐手法列出必需键。缺项返回 `needs_evidence`，
齐全也只返回 `candidate_requires_review`。不把这些状态当成素材已授权或视频已执行。

阅读时间默认取 `max(1.2, 阅读单位/5 + 0.4)` 秒，从 `textReadyOffsetSeconds` 后开始；
按画面实际字符估算，显式 `readingUnits` 只能提高预算，不能低报字符数。公式是保守
起点，复杂图表、陌生术语、老年受众需要更长时间。缺文字只给最小起点并报
`reading_content_not_measured`。真实反应默认至少 0.8 秒、现场声至少 1.5 秒；这些
也是可调起点，不能拉长表情、重复帧或生成环境声冒充现场。

区间不足返回 `insufficient_hold`，不会偷偷延长片段或改变 PTS。处理顺序是：
减字/分步揭示 → 选更长真实源段 → 获批重排时间线 → 用代表片段复核。

## 后台实施顺序

1. 先做内容首剪，保留完整条件、否定、原因、失败与结论；原素材只读。
2. 从最终时间轴生成带时间 cues，解析段落模板。导演计划中的
   `editingCraft.decisions` 记录每拍触发、缺口、候选、保护和声音意图。
3. 先处理 `editingCraft.issues`；证据不足时执行干净原镜回退，不能按候选硬做。
4. 对拟采用手法制作真实素材的局部 A/B。镜头处理走现有 Timeline IR / Render
   Graph，视觉效果走 `templates resolve`，每条使用记录保留 cue ID、源区间、理由、
   最简回退、源文件 SHA 和正常速度预览。
5. J/L-cut 使用独立音频铺轨或先生成绑定同一 EDL 的 dialogue stem；不要将 J/L
   解释成画面 dissolve，也不要把音频整轨偏移当作 split edit。编译器不支持的操作
   必须显式列为素材/实施缺口；当前新增模块不自动编译这些候选。
6. 保留现场声时使用真实源录音单独建轨。dialogue 分离的 residual 仍禁止回混；
   同期环境声也要核对录制地点、时段和同步，不能从网络补一个声音后称为现场。
7. 配乐按段落功能安排，不按镜头数量：建立 → 稍推进 → 证据退乐 → 结果或反思
   收束。音效只绑定动作/结果落点，优先项目私有音效库，字体和栏目品牌不变。
8. 核对渲染的真实声画结果，再跑连接、字幕、组件混音与完整 QC。候选手法和导演
   计划校验通过，不等于 J/L-cut、音效或现场声已经写入成片。

当前保护会实际降低导演计划的装饰性强调预算，保留原有开场计数但不强制高影响
开场。它不重写时间线，也不自动跳过生产包门禁；若内容与生产包配额冲突，应在
方案阶段明确处理，不为了过门禁虚构语义触发。

## 审片时看什么

先无音乐看结构与动作，再只听声音查语义和接点，最后正常速度看声画合成。
问题必须能够落到时间码：是否不知身在何处、动作是否重复、条件是否丢失、结果
是否读完、包袱是否提前、环境是否被音乐抹平、每次放大是否有信息增量。
不要用“高级”“电影感”“网感”作为唯一验收标准。
