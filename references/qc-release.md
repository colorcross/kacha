# QC、交付与完成边界

## 两级门禁

- v2 首剪/结构重做：`qc → gate-release`；
- v3 局部返工：`qc → gate-candidate`，只有 intent 为
  `release_candidate` 时再进入 `gate-release`。

`candidate` 只要求通用技术检查、变化层专项检查、冻结层不变性证明和动态
人工清单；它是可继续返工的候选，不是可发布成片。`release_candidate` 必须
重新以当前完整输出执行全量技术 QC、完整哈希和十一项人工审片。

v3 冻结层只能继承“没有变化”这一结论，不能复制旧报告：

- 只改画面：候选与基线音频 elementary-stream SHA-256 必须相同；
- 只改声音：候选与基线视频流 SHA-256 必须相同；
- 只改封面：不创建新视频，单独验证文件、哈希、精确画幅和人工封面检查；
- 任一流哈希、依赖指纹、几何或时间线不一致：对应层重新检查。

## 自动技术 QC

项目 manifest 定义最终媒体合同后运行：

```bash
node scripts/kacha.mjs qc PROJECT.json
```

自动检查：

- 最终文件存在和 SHA-256；
- 视频、音频轨；
- 分辨率、画幅、帧率；
- 音频采样率和声道数；
- 视频/音频时长差不超过项目允许帧数；
- 全片 FFmpeg 解码；
- 综合响度与 true peak；
- black、freeze、silence 探测；
- 编码、像素格式和色彩元数据记录。

black/freeze/silence 可能是计划内内容，因此探测结果只产生逐条人工判定任务。自动技术报告为 `pass_with_review` 不能被表述成“全片 QC 通过”。

## 必须人工完成的审片

`examples/release-report.template.json` 包含十一组必填检查：

1. `contentIntegrity`：完整语义、事实、数字、否定、因果和结论；
2. `connectionPlayback`：全部连接点正常速度试听；
3. `subtitleAccuracy`：字幕与最终声音一致；
4. `subtitleLayout`：真实字体、单行测宽、碰撞和平台安全区；
5. `visualContinuity`：景别、运动、转场、插镜回接和色彩连续；
6. `assetSemanticsAndLicenses`：外部素材语义与许可；
7. `maskTrackingBeautyAndPip`：蒙版、美颜、画中画和人物身份；
8. `audioStemAndDeviceListening`：voice/BGM/SFX、手机和耳机；
9. `coverAndBrand`：3:4、4:3、缩略图、安全框和品牌配置；
10. `openingEndingAndFullPlayback`：开头、结尾和全片通看；
11. `technicalFindingsDisposition`：逐条处理自动探测结果。

每项必须是 `pass` 并提供真实证据。证据可以是时间码清单、代表帧、对照图、stem 报告、试听记录或来源 manifest，不能写“已检查”作为唯一证据。

## 发布门禁

完成自动 QC 和人工报告后：

```bash
node scripts/kacha.mjs gate-release PROJECT.json
```

门禁会重新核对：

- 当前最终视频与技术 QC 的哈希一致；
- release report 与当前项目一致；
- 视频、封面和字幕真实存在；
- 所有交付物哈希匹配；
- 必要封面画幅齐全；
- 十一组人工检查全部通过。

只有该门禁通过，才能表述为“本地 QC 通过、可交付”。上传或平台发布仍是另一层授权和验证。

## 交付后的清理边界

release gate 通过不等于自动获得删除中间产物的授权。每次出片后只能先做 dry-run 盘点；只有确认用户不需要且能快速重建的缓存才能执行 `routine` 清理。

用户明确说明项目完成且不会再修改后，才允许执行 `final` 清理。清理前后都必须复核最终视频、封面、字幕、工程、方案、manifest、许可、QC/release 报告和用户指定保留项仍然存在，并把 `cleanup-report.json` 纳入交付记录。

## 全片检查细则

### 内容和连接

- 无半句、错误数字、错误专名、断裂因果；
- 无说错后废弃片段、无意义重复和无信息空闲；
- 保留必要呼吸、自嘲和自然强弱；
- 每个连接点无音量跳变、爆音、口型错位或突兀画面。

### 切镜和画面

- 切点有信息、情绪或视角理由；
- 同一主体相邻景别有可感知变化；
- 无 2–4 帧瞬闪、残帧、黑帧或模板转场掩盖错误切点；
- 高影响视觉模块的实现与已批准本地样式帧/Figma 设计、三态动效和声音交接一致；
- 多状态流程图/清理模块的底图保持稳定，只更新当前节点；逐状态边界检查活动区外无整屏亮度闪烁；
- 插镜对象、动作、状态、角色和时态完全匹配；
- 插镜首/中/尾和回到 A-roll 的交接帧通过；
- 画中画不遮关键证据，退出后无同源重复；
- 画中画使用完整原始构图等比缩小，人物头顶、下巴、肩部和关键手势未被
  固定矩形硬裁；圆形/方形变化也先完成 full-frame fit；
- 双屏各窗格的人物按独立轨迹居中，完整头顶保留，整体视觉重心向画面中心
  聚拢；
- 蒙版无漏抠、误抠、白边、黑边、抖动或身份切换；
- 美颜自然，脸颈手连续，背景和眼镜没有一起变软；
- 跨素材曝光、白平衡、肤色和运动语言一致。
- 插镜、字幕、画中画和临时卡片在切回主画面前 1–4 帧完成退出；
- `connectionAudit` 的检测数、cutSheet 数和正常速度已审数量一致，未解决连接点为零；

### 字幕和文字

- 字幕来自最终音频；
- 数字、专名、否定和结论复核；
- 单行、无意外换行、真实字体测宽；
- 阴影、强调和文字本体均在安全区；
- 亮底用深色变体，暗底用浅色变体；
- 逻辑重音与 SFX 同步且不过量；
- 人物后置文字可读，边缘合成自然。

### 音频

- dialogue 处理没有金属声、抽吸、齿音损伤和声道破坏；
- 参考版本同源同响度 A/B；
- BGM 可感知但不抢人声；
- 每个计划内 SFX 在最终成片可听；
- SFX 与 `sfxPlan.events` 一一对应，功能、音色和落点有区分，无整片单一音效滥用；
- 响度、true peak、声道和 48 kHz 合同通过；
- declared FPS 与 average FPS 都符合项目合同；
- 手机扬声器和耳机均已正常速度试听。

### 封面、开头和结尾

- 3:4 与 4:3 精确；
- 人物、标题、品牌和系列名零碰撞；
- 人物头顶、眼镜、脸和手势完整；
- 原尺寸和手机缩略图都可读；
- 无意静音片头不存在；
- 最后音节完整，默认只留 1–3 帧自然收束；
- 无尾静音、静态尾巴、冻帧或黑帧。

## 完成表述

必须明确区分：

- 已分析/已给方案；
- 已修改但未渲染；
- 已渲染但未完整 QC；
- 自动技术 QC 通过或 `pass_with_review`；
- 本地完整 QC 与 release gate 通过；
- 已上传；
- 已发布并在平台端复核。

不能用前一阶段冒充后一阶段。
