# 大灰AI剪辑系统 V1

依据：调用项目的《大灰AI｜自媒体IP实操方案 V6.1》。本文件规定咔嚓如何将它转成剪辑工程；选题、排期和产品事实仍以调用项目当期资料为准。

## 1. 重构后的制作顺序

**观众任务 → 一期主问题 → 栏目叙事 → 真实证据 → 剪辑结构 → 音画表达 → 审片。**

先完成这一条链，再决定某处要不要动效。大灰的独特判断来自读过的文本、做过的实验、开发和使用过的产品、实际对话与持续行动。包装应帮助观众看见判断过程。

- 默认真人口播，实际录屏、原文、图表与现场补充信息。
- 大众能听懂：一次解释一个必要概念；先说明它解决什么问题，再给术语。
- 单段必须有用途：建立问题、展示证据、解释关系、保留真实反应、推进判断或提供下一步。重复的装饰不能替代任何一种用途。
- 不强制片头动画、每分钟特效数、蒙版数量、固定字体、动漫人物、固定服装、栏目角标或期号。
- 不因此取消用户明确要求或事实表达必须使用的图表、强调、动效和音效。必需项及已触发的条件项都须映射到 Timeline IR。
- 新工程生产包 `dahui-ai`，叙事政策 `narrative-v1`，视觉 profile `dahui-ai`。旧 `xingzhe-dahui` 与已冻结工程保留；不批量迁移历史作品。

## 2. 八类剪辑方法

|栏目 / 内部ID|主片建议|先剪什么|必须可查的材料|声音与节奏|
|---|---|---|---|---|
|AI实践 `ai-practice`|5–10分钟|任务→输入→关键步骤→结果检查→成本→复用|真实输入、工具会话、输出、质量检查、总耗时/费用、可复用资料|以操作完整性为单位；等待可压缩并注明，结论退乐|
|AI拆解室 `ai-review`|6–12分钟|预设尺度→正常/边界/失败样本→对照→适用人群|测试协议、同条件输入输出、版本、样本记录、总成本|比较时停稳；同一量纲、同一裁切，观众有时间读数|
|AI访谈解读 `ai-interview`|8–20分钟|原问题→嘉宾论证→依据→我的分歧或认同→影响|完整访谈、原日期、源时间码、翻译与事实核查|引用与自己的话分开；不让配乐操控嘉宾态度|
|AI风向 `ai-news`|3–10分钟|变化→一手来源→开放状态→任务影响→判断|事件及发布日、官方材料、开放范围和核查记录|少而准，不追求滚动字幕和信息轰炸|
|灰常AI `ai-debate`|8–15分钟|命题→立场→挑战→最强反驳→条件→大灰判断|题卡、完整会话、工具版本、双方发言索引、剪辑披露、纠错|默认不在交锋下铺音乐；剪等待不剪成“被问住”|
|AI时代怎么读书 `ai-reading`|完整30–60分钟，目标40–50|一本书的论证→围绕问题穿插原文/AI回答/核查→整体判断|主书版本、已读范围、原文位置、AI输入范围与原始回答、理解核查|允许长停留和思考；章节分明，不连续推拉快切|
|产品实践 `product-practice`|5–10分钟|需求→选择→制作→迭代→真实使用→下一步|当期版本、开发记录、真实使用材料、AI角色|先让观众理解取舍，再展示界面；失败与局限有位置|
|运动与自我迭代 `life-iteration`|3–6分钟|情境→选择→行动→诚实复盘|带日期的实拍与本人记录|环境声优先，允许无音乐；不强行关联AI|

这些时长除读书母片外是制作建议，不是强制裁切目标。不得为了达标补拍假过程、删因果、拉长空镜。每条先解决自己的问题，再从现有证据决定最终长度。

### AI实践：让观众能够照着完成

先剪出“从输入到可交付输出”的完整链。屏幕内容只展示与当前步骤有关的区域；需要点击路径时保留位置关系，需要判断结果时放大结果，不反复全屏缩放。耗时明确区分模型等待、人的准备、核查和返工；费用标日期、版本、计费口径，不能把单次生成费用写成项目全部成本。结尾只交付本期真正可复用的流程或工具。

示例镜头顺序：大灰提出卡点 → 原材料 → 三步流程 → 每步关键输入/输出 → 人工验收 → 错误和修正 → 总耗时成本 → 资料与适用边界。未经实际测出的提升比例不能放封面。

### 读书：长片先立论证，再交替画面

一期只有一本主书，相关书可作为辅助材料。45分钟参考结构：0–2分钟问题；2–6分钟全书地图和共读范围；6–16、16–27、27–38分钟围绕三个核心问题；38–43分钟整体理解和AI的优势局限；43–45分钟读者可执行的阅读动作。此表是预算，最终章节时间码来自实际时间线。

每个问题可采用“作者怎样论证 → 我读到了什么 → 我给AI什么输入 → AI实际怎样解释 → 回原文检查 → 我修正了什么理解”。不必每章机械重复六步；文学作品允许多种解释，但须说明文本依据。保留AI答对、自己先前误解和仍未解决的问题。

原文画面带书名、版本及页码/章节；AI画面标工具版本、日期和输入范围。全文、节选、目录、摘要分别记录。先让观众看清引用，再继续解释；原文只截必要范围，不能用读屏速度取代理解。长片建立章节，保留整本书的主线，结尾回到开头问题。

衍生短片通常1–3分钟，只承载一个完整发现。另写独立开头，保留条件与证据位置，关联母片并沿用来源期号，不新计一期读书。

### 辩论：把互动真实性写进剪辑记录

录制保存大灰麦克风、AI输出、完整会话和屏幕；能分轨就分轨，并录同步记号。视频互动额外保存AI实际接收的画面，合成头像不等于模型有视觉输入。只能预设命题、方向和关键节点，不预写AI答案或胜负。

粗剪先按发言轮次整理双方立场，选出双方最强论据。一个反驳至少保留它反驳的命题和适用条件；不能只留下AI承认错误。技术等待可缩短，字幕说明等待已压缩；重连、重生成、补录和非连续拼接如实注明。异步文本配音明确标注，不称实时语音辩论。

字幕持续区分“大灰”和“AI”；引用、推测、事实纠错另用简短标签。核对否定词、转折、数量和说话人，不能从口型或声纹猜测。结尾表达大灰判断，不必有赢家。

咔嚓当前单源 Timeline IR 与已实现的声音编排能力继续有效；本次没有新增多机位自动同步、任意实时对话多轨合成或自动事实判真引擎。分轨素材的同步和接入须以当期工程实际能力检查，不能仅凭栏目配置称已完成。

### 测评、访谈、资讯：把归属说清楚

测评先写协议再录制。比较结果用相同量纲和完整条件；正常、边界及失败样本保留原记录。稳定性需要重复测量，单次样本只做单次结论。软件界面、价格、可用地区等以录制当日实际情况为准。

访谈给出原访谈日期、原始链接与时间码，节选保留原问题。字幕与画面区分“嘉宾观点”“已核实事实”“大灰判断”“未来预测”。外语原话与译文核对；含不确定语气时不得翻成确定结论。

资讯分别标明“公布、演示、邀请测试、已开放、本人实测”。一个新闻片集中说明一项变化及其影响；没实际测过不能用模拟界面暗示实测。不为排期补造热点。

### 产品与生活：用过程建立人格

产品从需求和选择讲起，保留至少一个取舍、一次具体迭代及实际使用结果。相交线、神硅、知著、小步、原界、吃相、Lumi 都按当期真实材料选择，不预设它们已上线某项功能。原型、本地运行、上线、设备使用、客户效果分别标注；AI辅助开发与AI原生分开。

运动记录实际日期、情境、困难和调整，不拍危险镜头补戏剧性，不将个人经历剪成普遍训练建议。现场没有得出结论，就允许本期开放结束。

## 3. 统一视听规则

- 真人、证据各自有完整的观看时间。插入画面回答“此刻观众需要看到什么”，不按固定秒数换镜头。
- 章节、比较和流程图是理解辅助；同一时刻一个阅读重点。大段引用先分层再呈现，不能同时堆满字幕、术语、页码与解释图。
- 字幕以最终音频为准，术语、人名、数字、否定和条件单独复核。字号和停留经手机观看检查；来源标签不能压住主字幕或关键证据。
- 选择本地已授权、覆盖当前文字的字体，记录实际文件和摘要。大灰AI允许清晰的系统/开源中文字体，不依赖旧品牌四款私有字体；不复制这些字体到公开包。
- 图表、画中画、重点词与镜头变化须有明确用途。让阅读停稳，不强制每分钟装饰量，也不把“克制”解释成删除必要解释。
- 默认自然问题、实际结果或现场动作开场。常规片争取20秒内清楚建立主问题；长书可用45秒。这是首版编辑上限供复盘调整，不是平台算法事实。自然动作和真实语音本身可承担吸引力。
- BGM默认关闭；需要时按章节/段落决定。辩论交锋、密集论证、原文引用和事实核查优先留白。音乐不等于专业，安静也不等于素材缺失。
- SFX先查调用项目私有库的 manifest、kacha-profile 和试听索引。`preferred_local` 仅在语义匹配时优先；普通字幕不配逐字音效，不为配额添声音。
- 生成图、素材库画面可作明确标注的示意，不能成为本人经历、工具实测、产品使用或书籍原文的证据。
- 封面用一个真实主题证据或本人照片与一个短问题；不强制真人、3D、服装、系列标签、期号。封面和标题里的数字须有当期材料支持。

## 4. 实际工具入口

工作台默认大灰AI，八个预设分别对应八栏目。选择栏目会同步其预设；旧五种风格显示“历史风格”。新栏目与历史风格混配会报错，避免静默回落。

```bash
node scripts/kacha.mjs episode list
node scripts/kacha.mjs episode template --project-id DH6-102 --show ai-reading --output /PROJECT/contracts/episode.json
node scripts/kacha.mjs start --source /MEDIA/main.mov --pack dahui-ai --show ai-reading --project-id DH6-102 --project-root /PROJECT
```

`/PROJECT`、`/MEDIA` 是调用者填写的路径。新工程会生成 production-quality 合同及其关联的 `.episode.json` 草稿；若已提前制作 `episode.json`，使用下方 bind 命令显式绑定，不要保留两份各自修改的节目合同。

```bash
node scripts/kacha.mjs episode bind --episode /PROJECT/contracts/episode.json --requirements /PROJECT/contracts/editorial-requirements.json --contract /PROJECT/contracts/production-quality-contract.json
node scripts/kacha.mjs episode validate --episode /PROJECT/contracts/episode.json --stage plan
node scripts/kacha.mjs production-quality validate --contract /PROJECT/contracts/production-quality-contract.json --stage plan
node scripts/kacha.mjs visual-capabilities template --style dahui-ai --show ai-reading --duration 2700 --requirements /PROJECT/contracts/editorial-requirements.json --output /PROJECT/contracts/visual-plan.json
node scripts/kacha.mjs cover template --pack dahui-ai --project-id DH6-102 --evidence /MEDIA/book-photo.jpg --output /PROJECT/contracts/cover.json
```

模板包含空值，表示待准备，不是通过证据。节目合同变更后用 `episode bind` 重新检查并更新 production-quality 中该文件的摘要；不得顺手清空其他已审阅的执行记录。已冻结项目继续使用绑定运行时，更新当前工具不自动重剪历史片。

### 节目合同与时间线的分工

`episode.json` 保存本期问题、受众任务、自己的判断、栏目环节、证据索引、主书/工具/版本/日期/输入范围、章节与辩论发言索引。真实文件用 path+SHA-256 绑定，并注明原文页码、源时间码或记录位置。

`beats[].timelineIds` 引用当前 Timeline IR 的执行对象。时间线仍是唯一剪辑事实来源；节目合同不能创造素材或延长镜头。执行检查核对映射是否存在、工程是否匹配；长书实际时长从 EDL 和转场扣除计算，不能仅填写2700秒骗过检查。

`editorial-requirements.json` 保留原有分层：用户或事实要求必须 required，条件增强注明触发情况，可选项注明采用/省略理由。节目合同不能替代它。

封面通过 `cover validate --require-qc-pass` 后，将其 path/sha256 绑定到生产质量合同的 `execution.cover.editorialContract`。

发布检查增加事实、归属、可读性、正常速度终审及终审记录文件。自动检查只证明结构和证据绑定，**不能判定引用真实含义、观点是否准确或成片是否好看**；大灰仍需看完整条片。

### 路径与能力边界

当前完整品牌门禁接入真人主叙事的单源工程：原文、录屏等通过既有证据素材与覆盖层加入。`materials` 自动拼接入口尚未具备本体系的栏目终审门禁，显式请求大灰AI会提示改用该主叙事工程，不会静默按通用短片拼接。此限制不影响原有通用素材工程。

本次重构交付的是工具、配置和可检查的制作规则。未导入某期真实素材、未做正常速度审片前，不能宣称某期成片已完成。

## 5. 大灰与剪辑协作者的交接

大灰交付：本期主问题、论证提纲、真人素材、实际证据、原始AI对话、不可删条件、自己的结论、待核事项。协作者交付：结构粗剪、证据索引、剪辑工程、字幕、章节、封面方向及未解决问题。

每条经历四个检查点：

1. **开剪前材料齐套**：缺核心输出、主书范围或完整对话时先补材料，不能用装饰替代。
2. **结构粗剪**：大灰确认论证、反驳、取舍和事实边界；此时不打磨无关动效。
3. **代表段精剪**：先看开头、最密集证据段、最容易误解的段落。确认手机可读、声画同步、观看速度。
4. **全片终审**：完整正常速度审片，确认事实、字幕、条件、章节和交付文件；之后导出母片和必要衍生。

读书一周一次完整母片，剪辑预算初始8小时；其他节目按项目V6.1协作班表分配。8小时是估算，复杂长片实际超时就记录原因，调整制作规模或排期，不跳过事实核查。母片、切片、跨平台版本分别登记，不重复计原创。

交付包：母片、最终字幕、实际章节时间码、封面、标题备选、来源说明、可复用资料、工程与证据索引、审片记录、待续问题。竖屏衍生重新适配证据阅读区，不能直接中心裁切横屏界面。

## 6. 迁移与验证

- 不批量改名旧视频、期号、栏目目录或运行时；新内容才使用新包。
- 旧 `very-ai` 是历史栏目路由，新辩论是 `ai-debate`；同名“灰常AI”若对外显示期号须先查历史最高已发布编号。
- `tests/dahui_editorial_tests.mjs` 覆盖八类路由、旧包保留、节目草稿、证据变更、读书长度、章节、真实时间线和终审记录等；夹具通过不等于实拍验收。
- `make check-full` 后同步 Codex/Claude 安装并核对摘要。双安装更新不代表历史工程运行时自动迁移，也不代表公开版本发布。
