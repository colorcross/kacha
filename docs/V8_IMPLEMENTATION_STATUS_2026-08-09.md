# 咔嚓 V8 实施状态（2026-08-09）

## 已实现

- `config/efficiency-policy.json`：质量不变量、风险、代表区间、资源、缓存和声明门禁；
- `scripts/quality_efficiency.mjs`：`plan/validate/schedule/execute/cache-audit/compare`；
- `.kacha/efficiency-inputs.json`：独立冻结当前 cues/delta，支持计划损坏后的安全恢复；
- V3 增量计划直接写入最多三段、完整覆盖变化点的代表区间；
- 十三阶段依赖、资源、并行安全和输出组合同；
- 自动任务经过主机资源锁与运行遥测；
- `start/run/resume/status` 自动维护效率计划和缓存证据；
- Studio 项目页与统一审片观察区显示同一效率摘要；
- 五项 V8 定向合同测试，仓库总回归增加到 136 项。

## 深度 review 后的加固

- 全范围增量不再生成零段预览；固定选开场、复杂视觉和结尾三段待确认样本；
- 分散变化用动态规划最小化总覆盖跨度，只有不可避免的长段才声明预算例外；
- 计划验证从当前 orchestration、cues、delta、policy 和 recipes 重建风险、区间、
  覆盖与调度，重算 digest 不能绕过质量或编码预算；
- 自动执行只接受登记脚本、当前实现 SHA 和参数级输出绑定，并在任务结束后再次
  拒绝符号链接或越界输出；
- 缓存审计重算 contract key，验证精确输出 schema、文件数和当前产物内容，拒绝
  缓存路径符号链接；预热覆盖率改为只统计阶段计划声明的预期内容键，不能用同种类
  的任意旧条目冒充当前命中；
- 效率比较要求真实可解码源片与含音轨输出、不同输出、当前结构化人审/指标/护栏
  文件，以及两边完全一致的八项目 ID；格式正确但不存在的 SHA 不再算证据；
- `status/observe` 每次按当前文件重验，损坏计划成为可恢复阻断，`run` 可安全重建。

## 已证实层级

- 静态 schema、CLI 和 DAG 可验证；
- 代表区间覆盖、强指纹缺失阻断、并行任务实际落盘与遥测可回归；
- 少于八个项目或关键质量护栏退化时，效率声明会失败。
- V8 五项定向测试和 V7 损坏计划恢复测试覆盖上述 review 缺陷。

## 尚未由代码替代的真实证据

- 至少 8 个真实、同源成对、真人审片项目的实际墙钟时间；
- 真实 Final Cut Pro、Premiere 或 Resolve 往返；
- 4K 完整候选的正常速度人审；
- 不同机器、不同栏目和不同风格下的外推结论。

在这些证据完成前，只能称为“效率合同和执行能力已实现”，不能声称生产平均时间
已经降低某个百分比。
