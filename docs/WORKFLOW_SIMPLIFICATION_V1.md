# 能力适配与工作流精简 V1 · 2026-10-15

新工程减少重复规划、串行等待和无差别重做；Timeline IR、实际声画QC、权限与当前候选终审保留。基线为 `1e7daf5`。本轮是工具流程改进，没有真实节目同源成对的效率结论。

## 用户与Agent接口

用户只需理解素材、形成初稿、针对问题修改、验证交付四步。内部专业节点保留为依赖与证据对象，不要求用户填写JSON，也不因阶段数要求多轮模型调用。模型可以一次理解内容并联合决定粗剪、精剪、素材与声音；CPU/MPS/编码任务仍受原资源锁约束。

新单源manifest和proposal均使用 `workflowPolicy: {version: "adaptive-v1"}`。省略proposal.executionFlow时自动生成适用节点；已有完整executionFlow也可验证，但不得突破依赖。缺政策字段的历史工程继续legacy；不根据“用了新模型”迁移历史工程。

`prepare --execution-mode adaptive|guided --capabilities FILE` 的能力文件包含schemaVersion=1.0、imageInput/audioInput/videoInput布尔值和实际会话evidence。未声明为unknown。它描述接入能力，不授予权限，也不是模型已经查看了素材的证据。默认非economy采用adaptive；economy采用guided。显式 --stage 仍是上下文读取边界。

`next` 给出当前建议、可用节点及其 expectedInputDigest。按这个摘要提交 `state record --expected-input ...`，程序锁内复核当前工程；不再用旧对话记忆推进。脚本不代写人工通过结论。

声音命令及诊断/处理回执见 `references/audio.md`。当前无分离路线只处理诊断绑定的一个源音轨，按当前EDL、转场与源起始偏移输出剪后独立PCM。处理回执绑定映射摘要，改剪点后必须重建；其他音轨或复杂混音先保持原路径，不能把未知录音当干净录音。

## 保留与兼容

- material_edit 继续既有素材工程执行器，v3小改动继续增量执行器，二者不为了“统一”重走新单源方案。它们共用能力路由、媒体工具和实际验收。
- 旧冻结运行时保持原身份。明确的源分离、必需表达、付费/上传范围和输出规格不由新默认放宽。
- stage状态不是最终放行；实际产物、字体、素材许可、声音组件、节目证据、母片/衍生和封面终审仍经既有门禁。
- 首剪的edit plan、导演计划和质量合同仍分别表达时间映射、叙事选择与验收结果。本轮去掉重复阶段手填和历史规则重读，没有把职责不同的产物机械合并成巨型文件。

## 验证与后续量化

专项 `tests/workflow_simplification_tests.mjs` 纳入 check-specialized、check-full、远端CI和安装检查。使用真实本地合成音轨验证解码、PCM直通及处理结果；语义审听使用明确synthetic合同夹具，不冒充真人节目。

效率验证应固定模型、源素材和交付要求，比较旧/新任务的首次可播放时间、Token、工具往返、处理次数、人工介入、返工与成片质量；不能由减少文档或节点等待推导整体提速百分比。新模型的上下文/视觉能力每次按实际入口核实，模型自述置信度不替代输出验证。

## 独立复核修复

复核用真实合成媒体和实际 `next → state record` 调用检验实现。已补齐终审/交付登记摘要、已知时间线合同的分区失效、上游证据变化的后继失效和“不适用”节点的祖先依赖；声音路径补齐剪后映射、起始偏移与硬链接释放后的文件身份记录。对应回归覆盖20项，不以合成声音证明真人语义审听。
