# 咔嚓 v3 增量工作流

## 目标

v3 解决的不是“少做质量检查”，而是“只重做真正发生变化的部分”。它在
v2 完整首剪流程之上增加一条增量路径：

1. 项目第一次建立稳定基线；
2. 后续反馈只记录相对基线的变化；
3. 通过依赖图判断哪些产物失效、哪些可以复用；
4. 只渲染受影响的媒体层或时间区间；
5. 对变化层执行专项 QC，对冻结层提供哈希不变性证据；
6. 工作候选版与最终发布版使用不同门禁；
7. 最终发布仍执行完整技术 QC、人工通看和 release gate。

v2 的 `editProposal`、`edit plan` 和十三阶段继续用于整支首剪、内容重构和
跨版本重做。v3 不要求旧项目立即迁移，也不降低语义完整、音画同步、源文件
只读和禁止覆盖等质量红线。

## 五个文件

### `project-context.json`

项目级稳定事实，只创建或重新锁定一次：

- 项目根目录、源文件和基线成片；
- 文件 SHA-256、大小、修改时间和媒体规格；
- 创意锁定、输出几何、前台主体和 AI 角色；
- 系列身份、交付范围、授权和策略 profile；
- 当前 artifact index。

局部返工不重复书写内容主线、完整模块表或十三阶段。

### `version-delta.json`

一轮反馈只记录：

- 基线版本和目标版本；
- `preview`、`candidate` 或 `release_candidate`；
- 修改类型、变化层、影响区间和是否改变时长；
- 新输出、封面或字幕；
- 验收条件和用户原话证据。

冻结层由变化层的补集推导，不要求每条反馈重复列出。

### `artifact-index.json`

所有可复用产物的登记表：

- 路径、类型、版本、SHA-256 和内容指纹；
- 依赖项、时间范围、工具和参数哈希；
- 是否仍被当前版本引用；
- 用户是否需要、是否参与返工、重建速度和成本；
- 是否来自付费生成或人工校准。

只有依赖和指纹都匹配的产物才能命中缓存。

### `incremental-plan.json`

由脚本从 context、delta 和 artifact index 自动生成，不能由自然语言冒充：

- L0–L3 影响级别；
- 推荐渲染策略；
- 失效和复用的 artifact；
- 必须执行、可以继承和必须人工检查的 QC；
- 最小预览范围和前后 handle。

### `delta-qc.json`

当前候选版本的增量技术证据：

- 当前输出 SHA-256；
- 本轮实际执行的检查；
- 冻结音频或视频流的 elementary-stream SHA-256；
- 继承证据对应的基线文件、版本和哈希；
- 仍需人工检查的变化层项目。

## 影响分级

| 等级 | 典型变化 | 默认策略 |
| --- | --- | --- |
| L0 | 容器、MOV 时间基、色彩元数据 | `metadata_rewrap` |
| L1 | 封面、字幕、BGM、SFX、美颜、调色等单层变化 | `no_video_render`、`stream_copy_video`、`stream_copy_audio` 或 `layer_rebuild` |
| L2 | 局部插镜、PIP、转场、局部多层联动 | `segment_rebuild`，带前后 handle |
| L3 | 删除、重排、补录、改画幅或改变时长 | `full_rebuild` |

影响级别由脚本推导。用户或 Agent 可以请求更保守的策略，但不能把 L3 手工
降成 L1/L2。

## 版本意图

### `preview`

- 只验证代表帧、短区间、A/B 或声音样例；
- 不要求完整视频；
- 不生成 release report；
- 不能称为成片或可发布版本。

### `candidate`

- 可以是完整候选视频或封面/字幕专项候选；
- 完成通用技术检查和变化层人工检查；
- 允许继续返工；
- 不能称为本地完整 QC 通过。

### `release_candidate`

- 当前输出必须是完整成片；
- 完成全片解码、完整技术 QC、十一项人工审片和 release gate；
- 只有该状态才能进入本地最终交付。

## 分层 QC

### 永远执行

只要输出是完整视频，就检查：

- 文件存在、非空和 SHA-256；
- 完整解码；
- 尺寸、画幅、帧率和时长；
- A/V 时长差；
- 基线未被覆盖。

### 音频层变化

执行响度、true peak、采样率、声道、A/V 漂移和设备试听。视频冻结时比较
基线与候选的视频 elementary-stream SHA-256。

### 视频层变化

执行 black/freeze 探测、几何和对应的字幕/美颜/蒙版/连续性检查。音频冻结
时比较基线与候选的音频 elementary-stream SHA-256，不重复判定响度。

### 封面变化

不渲染视频，只检查文件、哈希、精确画幅、标题、人物、品牌、系列标识和
手机缩略图。

### 最终发布

增量证据不能替代当前完整输出的全片通看。`release_candidate` 仍要求十一项
人工检查全部属于当前输出版本。

## 缓存与失效

缓存键至少包含：

```text
源 SHA + 时间区间 + 宽高/FPS + 工具版本 + 模型版本 + 参数哈希
```

典型规则：

- 只改 BGM/SFX：不使转写、字幕、Vision 蒙版或美颜跟踪失效；
- 只改美颜参数且时间线、几何不变：复用皮肤蒙版；
- 改字幕文字但不改时序：复用词级时间码和音频；
- 删除或重排：所有时间相关的字幕、混音、插镜和最终合成失效；
- 改画幅：重做布局检查；源坐标蒙版只有与视频使用同一变换时才可复用；
- 工具、模型或关键参数版本变化：对应缓存失效。

不知道是否安全时选择重建，不能为了命中缓存放宽身份检查。

## 最小预览

- 静态样式：3–5 张代表帧；
- 跟踪、美颜、蒙版：包含正脸、转头、遮挡和边缘的 1–2 秒片段；
- 转场和切点：切前、切后各至少 1 秒并包含真实 handle；
- 音频：同源、同响度 A/B；
- 预览参数冻结后，其蒙版、跟踪和样式帧进入 artifact index，正式渲染不得
  无条件重算。

## 清理联动

artifact index 自动生成清理候选，但仍只生成 dry-run：

- `routine`：用户不需要、当前无引用、已验证快速重建；
- `final`：用户明确确认不再修改后，才允许处理代理、蒙版和中间编码；
- 付费生成、重新下载、人工校准和耗时推理不属于例行缓存；
- 原始素材、当前/基线成片、方案、manifest、许可、QC 和批准 stem 始终保护。

## 公共 Core 与私有 Overlay

公开仓库是唯一 core 源。机器专属后端、绝对路径、私有运行时和不公开实现
放在仓库外 overlay。同步时：

1. 从公开 core 构建临时 bundle；
2. 对 overlay 做路径白名单检查；
3. 应用 overlay 文件或补丁；
4. 运行公开回归和私有专项回归；
5. 原子同步到 Codex 和 Claude；
6. 比较两端 bundle hash；
7. 保留旧安装备份，失败时不替换当前可用版本。

公开提交前继续运行 secrets scan，overlay 不进入 Git 暂存区。

## 建议指标

每次运行写入 `run-metrics.json`：

- 本轮读取的 reference 和字符数；
- 路由后的文件数、近似输入 token 与实际模型档位；
- 计划文件大小；
- 变化层和受影响时长；
- 重渲染时长占整片比例；
- artifact 缓存命中率；
- 实际执行和继承的 QC 数量；
- 本地/远程视觉证据状态、采样帧数和整片是否上传；
- 渲染、QC、测试和同步耗时；
- 中间产物峰值与清理候选空间。

没有这些数据时，只能把“节省 40%”作为目标，不能写成已验证收益。
