## 产品判断与实施方案

咔嚓已有内容编排、Timeline IR、可撤销编辑、渲染、审片和交付模块。本轮围绕
“可靠执行、可恢复、说清下一步”打通现有能力，保留 Agent 对话为主要入口。

| 优先级 | 问题与用户影响 | 本轮实施与验收 |
| --- | --- | --- |
| P1 | 后台任务可以认领已有文件；同时输出同一路径可能覆盖 | 提交和执行双重检查，执行期输出锁；用已有文件、并发任务和失败重试验证 |
| P1 | `--` 后子命令参数可能改变 jobs 自身选项 | 严格分离控制参数和子命令参数；验证参数隔离 |

| P1 | 取消仅处理直接子进程，恢复未确认旧进程退出 | 管理 POSIX 子进程组，取消后复核；拒绝活进程恢复，验证孙进程不再写文件 |
| P1 | 任务目录与内部路径边界不完整 | 拒绝特殊 ID 和越界链接，独占创建任务目录；验证外部文件不受影响 |

## 本轮产品改进

1. **清楚的进度答复**：`status --summary` 给出四里程碑和唯一下一步，由 Agent 翻译成用户能直接理解的进度。
2. **可操作的失败说明**：任务结果包含恢复建议、当前进程状态、日志位置；坏记录单独列出，不必翻完整任务历史。
3. **可靠的返工**：输出有归属，失败返回真实退出码，取消包含子进程组，恢复不会与旧执行重叠。
4. **轻量的校正工作区**：用素材、画面、调整、时间线、修改记录组织操作，窄屏保留制作与审片导航。
5. **可持续的验证**：产品数字来自共享事实文件，代码、媒体、依赖和分发分别检查。浏览器检查是可选入口，不进入默认全量门禁。

## 兼容性说明

- `jobs submit/resume --foreground` 失败现返回退出码 1，调用方仍可解析 stdout 的终态 JSON。
- `jobs list` 默认返回 20 条，调用方使用 responseWindow 分页，状态计数覆盖扫描到的有效记录。
- 旧任务合同继续可读；旧任务缺少进程组字段时只能使用已有 PID 证据。
- vinext 从 0.0.50 升至 1.0.0-beta.9，仍属于 beta 构建器；本轮验证静态站和本地 SSR，不代表线上部署。
- POSIX 进程组覆盖普通子孙进程，主动 setsid 脱离组的外部程序不在保证内。
