# 多素材按要求成片：实现与验收范围

用户交付视频、图片和自然语言要求后，咔嚓现在有独立的 `material_edit` 入口。
Agent 完成内容审阅和镜头选择，确定性工具执行经过校验的分镜并生成候选。
用户不必整理时间线数据或编写 JSON。

## 需求与实现

| 用户需要 | 已实现 |
| --- | --- |
| 一次交付多个文件或目录 | 多路径递归导入、重复路径去重、媒体探测、源文件强身份冻结、跳过条目清单 |
| 按主题和限制挑素材 | 原始要求留存、Agent 实际审阅帧与选段观察、逐项要求覆盖、必用/禁用素材检查 |
| 从长视频中取片段、穿插图片 | 视频源区间校验、静态图片定时保持、逐镜源时间映射、镜头顺序与总时长检查 |
| 混合横竖屏、帧率和声音 | 完整适配或有理由的居中裁切、统一帧率、48 kHz 双声道、原声/静音和可选本地配乐 |
| 清楚可读的说明字幕 | 沿用品牌字体、字幕安全区、单镜头短说明与最低阅读时长检查 |
| 出错后继续、修改后重剪 | 后台任务去重、取消/恢复、版本化计划和候选、片段缓存复用、旧版产物保留 |
| 知道当前进行到哪 | 标准 status 汇总素材、分镜、渲染、审阅四个里程碑，候选与人工验收分开 |

## 技术取舍

复用已有单源 Timeline IR 和 Render Graph：只对选用区间做 FFV1/PCM 无损
归一化，随后无损拼接为母版，字幕与配乐进入统一成片编码。这样避免改坏现有
口播生产路径，也避免将多次有损转码伪装成一次成片编码。代价是无损缓存会占用
较多磁盘空间。源素材保持只读，缓存清理继续受既有项目完成与源文件保护规则约束。

全局原始要求或源素材改变时建立新项目，分镜、字幕和选段改变时生成新的编辑
版本；不覆写已冻结合同。排队任务绑定计划摘要，防止用户改分镜后旧任务无意
渲染新版本。成片记录还绑定当前输出、时间线和母版身份。

## 验证

专项入口：`node tests/material_project_tests.mjs`。它会生成本地合成视频和图片，
实际完成横屏混剪、非零源区间选择、纯图片竖屏配乐及后台任务取消和恢复。
通过解码像素和音量检测检查顺序、选段及原声/静音；检查字幕返工和选段修改的
缓存复用差异，并验证要求、时间边界、源文件变化和越界写入保护。

专项并入既有 V7 核心回归，全量入口为 `make check-full`，覆盖静态检查、任务
可靠性、核心回归、MCP、分发和隔离安装。实际运行日志与本地同步回读单独保存，
不以文档存在代替检查通过。验证无需浏览器。

## 当前能力边界

本入口可交付技术可用的候选；合成回归不证明真实节目达到特定审美水平。
Agent 需要根据实际素材完成叙事判断，并查看候选连续画面和试听声音。
帧提取不等于全片理解，要求引用不等于语义自动验真。现有短说明字幕不是自动
逐字 ASR 字幕；4K、变速、HDR 色彩管理和跨镜头 J/L 音频重叠尚未在此分镜
合同实现；PQ/HLG HDR 输入会阻断并要求先明确转换到 SDR，避免静默错误转换。
有长音频尾巴的文件以视频轨时长限制选段。已有专业模块可按需要继续处理，不能把规划文件称为效果执行。

详细操作与合同见 [多素材成片参考](../references/material-editing.md)。

安装后验收同时修复了运行版本识别：无 Git 的安装副本在只读状态检查中保留
合法的 `.kacha-version`，不能将版本改写为 `not-a-git-checkout` 而误报失配。
两端实际内容摘要仍逐一比较；元数据损坏或任一安装内容变化仍会阻断。
