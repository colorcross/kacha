# 行者风 3.0：电影化编辑与反网页执行合同

## 1. 结论

行者风 3.0 不是一套新色板，而是一次画面权力重排：

1. 真人、真实空间、屏幕录制和可核验证据是主画面；
2. 蒙版、遮挡、运镜、切景和无边界排版是主要包装手段；
3. 卡片、弹窗、栅格只在信息确实需要边界时短暂出现；
4. 字体、颜色、圆角和阴影不再被当作“风格已实现”的证据；
5. 任何静态峰值帧都不能代替正常速度的动态审看。

行者风的理想感受是“一部正在被编辑的真实影片”，不是“一个装进视频尺寸的网页”。

## 2. 根因与迁移目标

旧实现的主要问题不是暖橙或玻璃材质本身，而是高频场景反复采用
“左卡片 + 右人物”、居中弹窗、等宽列表和全屏信息画布。五种风格即使
换了色彩、纹理和动画，仍共享同一网页拓扑，因而看上去像换皮。

迁移完成后：

- 高频信息场景默认使用负空间、边缘旁注、全画幅证据或渐进关系；
- 不再存在 `subject_left_card_right` 和高频信息场景的默认 `soft_pop`；
- 有边界表面不得相邻，单次不超过 8 秒，退场后至少返回 1.2 秒干净画面；
- 任何通用 dashboard、网页 hero、三卡等分、浏览器框和卡片接卡片均阻断交付。

## 3. 画面选择顺序

每个语义拍按以下顺序选择，只有前一项不足以说清内容时才进入下一项：

1. 原镜头重构：变景别、改构图、关键帧、节奏性推拉；
2. 真实证据插镜：实拍、屏录、原书、项目文件、来源截图；
3. 空间分层：人物蒙版、前景遮挡、画中画、焦点转移；
4. 无边界排版：大字、边缘旁注、逐行关系字幕、空间标注；
5. 画面关系：全屏证据、分屏对比、反应插格、过程路径；
6. 有边界表面：只用于引文来源、精确数值、复杂对比、渐进清单和必须保持分组的数据。

每个选择必须记录 `semanticBeatId`、`trigger`、`mechanism`、`sourceType`、
`containerType`、`compositionSignature` 和 `simplerAlternative`。

## 4. 五栏目画面预算

| 栏目 | 真人/真实空间/可核验证据最低占比 | 卡片/弹窗/有边界表面上限 | 120 秒内最少机制数 |
| --- | ---: | ---: | ---: |
| 工具分享 | 68% | 22% | 5 |
| 解读好书 | 72% | 16% | 3 |
| 有限的无限游戏 | 85% | 10% | 3 |
| 灰常AI | 70% | 20% | 5 |
| 闲聊 | 78% | 12% | 3 |

dashboard 占比永远为 0。上限是红线，不是建议用满的配额。

能力覆盖不再要求每个视频机械集齐十几种效果。除开场、必要支撑素材、语义动效、
关键帧变化、字幕关系和画面呼吸外，其余家族默认由内容触发；前 60 秒的吸引力由
独立首分钟合同控制，后续段落允许长时间保持干净真人或真实证据画面。

## 5. 五种子风格的不同镜头语法

### 5.1 浅暖轻浮层：编辑旁注

- 基本单位：一个完整口播意思；
- 主机制：运镜重构、无边界大字、真实证据插镜、细节切入、匹配切；
- 空间：从边缘和视线反方向进入，不把画面切成一排卡片；
- 声音：大部分旁注无音，重大落位最多一枚纸张或空气声。

### 5.2 空间光路：一次完成的空间导航

- 基本单位：一段真实关系或路径；
- 主机制：空间标注、前景遮挡、蒙版揭示、人物后文字、运镜重构；
- 空间：固定世界坐标与前中后景，节点不是浮在人物旁边的弹窗；
- 声音：起点与终点共用一条方向性 tonal phrase，不每个节点“叮”一次。

### 5.3 幽默漫画：喜剧时间

- 基本单位：铺垫—期待—反应—包袱—回扣；
- 主机制：反应插格、细节放大、匹配切、无边界短字、干净 A-roll；
- 空间：主画面 + 短暂反应插格，不是常驻三格漫画页；
- 声音：沉默本身是节奏；动作后最多一枚干燥短音，禁止罐头笑声。

### 5.4 像素风：确定性状态机

- 基本单位：输入—处理—状态—结果；
- 主机制：屏幕证据聚焦、无边界文字、细节插入、分屏关系、干净 A-roll；
- 空间：图形层遵守整数网格，人物、证据和正式文字保持高清；
- 声音：只在真实输入、确认、计时、奖励或错误发生时出声。

### 5.5 暗黑科技风：证据取证

- 基本单位：异常—假设—证据—裁决—恢复；
- 主机制：真实证据切入、蒙版揭示、前景遮挡、屏幕证据聚焦、干净 A-roll；
- 空间：局部观察孔、至多两层证据和一个裁决区，不是赛博 HUD；
- 声音：只在证据锁定或裁决可见落位后使用一枚干燥低频诊断音。

## 6. 高频场景迁移表

| 旧套路 | 3.0 默认 | 仍允许有边界表面的条件 |
| --- | --- | --- |
| 单信息卡 | 负空间旁注 | 需保持独立来源或精确数值 |
| 多要点卡 | 沿视线方向逐项建立 | 多组数据必须同时比较 |
| 三理由 | 编号与横向节奏线 | 不使用等宽三卡 |
| 定义卡 | 术语大字 + 逐行解释 | 长引用可使用来源版 |
| 金句卡 | 全画幅编辑式引文 | 有正式来源时使用来源版 |
| 警示弹窗 | 边缘警示 + 原画面反应 | 必须确认的高风险操作 |
| 对比卡 | 分屏证据关系 | 数值维度过多时使用对比表面 |
| 清单弹窗 | 随口播逐项落位 | 同时回看多项才有意义 |
| 画中画 | 有信息差的证据窗 | 禁止把同一 A-roll 缩小叠在自己上 |
| 人物后大字 | 2–7 字、蒙版建立纵深 | 文字较多时改为逐行关系字幕 |

## 7. 字体、动效、声音与常驻品牌

- 常规字幕：真正金陵体，无底色、无描边、阴影 60%；
- 视频标题、术语、金句和大号字：华光标题黑，仅在语义峰值使用受控透明渐变；
- 封面主标题：封神榜书；期号、来源和其他支撑文字：细体；
- 一拍只有一个主运动；清单与多行字幕必须随语音逐项/逐行出现；
- 音效以波形峰值对齐可见落点，不得把音效文件开始时间当作峰值；
- BGM 按语速、情绪、内容密度分段编排，通过乐器、BPM、和声、音色与高低频让人声更清楚；
- 品牌角标、栏目、期号和系列标识可常驻，但必须低对比、避开人脸/字幕/平台 UI，不显示“行者·某风格”文案。

## 8. 生产数据与门禁

权威机器合同：`config/design-system/anti-web.json`。新建项目的
`production-quality-contract.json` 会冻结当前合同摘要和 SHA-256。

每个成片镜头事件至少包含：

```json
{
  "id": "shot-014",
  "semanticBeatId": "beat-006",
  "trigger": "两个实验结果需要对比",
  "mechanism": "split_relationship",
  "sourceType": "project_evidence",
  "containerType": "none",
  "compositionSignature": "split-evidence-diagonal",
  "styleId": "xingzhe-pixel-editorial",
  "simplerAlternative": "仅用口播串行说明",
  "startSeconds": 42.4,
  "endSeconds": 47.2
}
```

自动计算并写回反网页指标：

```bash
node scripts/kacha.mjs production-quality anti-web-audit \
  --contract PROJECT/contracts/production-quality-contract.json --write
node scripts/kacha.mjs design motion-preview \
  --output design/reference-gallery/xingzhe-v3/normal-speed-previews --overwrite
node scripts/kacha.mjs production-quality validate \
  --contract PROJECT/contracts/production-quality-contract.json --stage release
```

发布前还必须提交：

- 有文件身份的正常速度代表预览；
- 手机缩略尺寸可读性审查；
- “是否像网页”人工审查；
- 整片正常速度播放和手机/耳机听审。

## 9. 实施与验收顺序

1. 冻结原片、字稿、栏目、风格和设计 digest；
2. 完成语义剪辑和全部连接点审计；
3. 先给每拍选择镜头机制，再解析组件和动效合同；
4. 运行 `anti-web-audit --write`，在渲染前修正占比、重复构图和容器连用；
5. 只渲染 1–3 段代表区间，正常速度检查声画、呼吸与网页感；
6. 通过后才完成全片代理与正式编码；
7. 用 `production-quality validate --stage release` 和整片人工审片收口。

## 10. 完成定义

以下条件同时成立才算完成行者风 3.0 交付：

- 设计系统、风格 profile、场景、组件和生产合同的摘要一致；
- 基础图库、五套高保真库与合同注册表只保留一个 `authoritative` 产物集，目录中不存在旧版本、失败 staging 或清单外孤儿文件；
- 每张高保真图的 `renderPlan` 与对应合同的 `visualExecutionPlan` 完全一致，1200 个合同 ID 唯一且矩阵完整；
- 不存在禁用的 UI 布局和卡片连用；
- 五种风格的镜头机制不是同一拓扑换材质；
- 参考图以全画幅视频峰值帧呈现，不再用网页式文档外壳包裹场景；
- 动态预览和正常速度人工审查通过；
- 自动测试、设计验证、矩阵 QC 和发布合同均通过。
