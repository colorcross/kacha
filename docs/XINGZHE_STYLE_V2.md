# 行者风 2.0 完整实施规范

## 1. 定位

行者风不是“暖橙色卡片风”，而是适合行者大灰真人口播、工具演示、深度内容和
真实记录的一套视频表达系统：

- 真实：主体、空间、素材与声音不被包装吞没；
- 有判断：颜色、景别、转场和动效都说明信息、情绪或视角变化；
- 克制但不沉闷：普通段落停稳，题眼、冲突和结论形成清晰峰值；
- 高级而可读：中性色承担大面积，强调色只承担明确的语义角色；
- 可复现：设计值、栏目差异、参考图、渲染器和验收规则都有唯一事实源。

## 2. 真实拍摄画面的基线

行者风首先依赖原片，不依赖后期“救画面”：

1. 采用负空间构图。人物优先处于左/右三分之一，给标题、证据或演示画面留出
   不少于画面宽度 30% 的连续净区；
2. 眼睛位于画面高度约 38%–42%，头顶留出稳定余量；
3. 书架、桌面和环境是内容证据，不是装饰。背景饱和度比人物降低约 8%–16%，
   细节略软但不可糊成假景深；
4. 人脸曝光优先，桌面高光不能成为第二视觉中心；
5. 通过远、中、近、特写的真实信息差建立节奏，不用持续数字推拉替代构图。

## 3. 色彩系统

### 3.1 基础色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 画布 | `#F2EFE8` | 暖灰背景、大面积留白 |
| 表面 | `#FBF8F1` | 卡片、信息层 |
| 主文字 | `#25282B` | 标题、正文 |
| 次文字 | `#626A70` | 标签、说明 |
| 品牌暖橙 | `#E98A2B` | 栏目、期号、普通强调 |
| 冷灰蓝 | `#6F8795` | 辅助层级、结构 |
| 信号珊瑚 | `#F05A47` | 冲突、否定、笑点、强落点 |
| 理性蓝 | `#5577B8` | AI、系统、信息/视角变化 |
| 验证绿 | `#3F8A78` | 完成、通过、证据成立 |

### 3.2 为什么不再只用暖橙

暖橙适合品牌和友好强调，但在“文字从人物后面出现”、强结论、冲突或反应上，
单色容易显得温吞。行者风 2.0 引入语义色，而不是引入更多装饰色：

- 暖橙：品牌归属、章节和一般重点；
- 珊瑚：冲突、反差、否定、喜剧落点；
- 理性蓝：AI 回应、概念切换、系统和视角；
- 验证绿：完成态、证据成立、结果；
- 普通字幕、长文、卡片正文仍使用深灰/暖白，不染成彩色。

### 3.3 渐变规则

只允许两组主要渐变：

- `brandWarm`：`#F5B544 → #E66A32`，用于品牌主峰、封面小面积锚点；
- `signalWarm`：`#FF8A3D → #F0445A`，用于人物后大字、冲突和强落点；
- `aiDialogue`：`#637FBE → #4C9B9A`，用于 AI 对话与系统节点。

约束：

- 渐变区域通常不超过画面的 12%–18%；
- 不用于整块普通信息卡、整句普通字幕或大面积背景；
- 一屏只保留一个主渐变焦点；
- 运动结束后必须停稳，不能让渐变持续流动制造“科技感”。

## 4. 栏目差异

五个栏目共享字体、空间、材质和品牌基因，但效果密度不同：

| 栏目 | 视觉气质 | 主要证据 | 效果策略 |
| --- | --- | --- | --- |
| 工具分享 | 实、快、可复现 | 界面、步骤、结果 | 节奏较快，PIP、流程和局部聚焦较多 |
| 解读好书 | 稳、深、完整 | 原书、引用、来源 | 降低强动效，章节、引文和停稳优先 |
| 有限的无限游戏 | 真、动、变化 | 现场、过程、时间 | 环境声和事件画面优先，包装服从真实 |
| 灰常AI | 活、险、可检验 | 对话、反应、核验 | 冲突和反应可以更强，事实区间自动收稳 |
| 闲聊 | 松、真、有判断 | 具体触发、个人观察、条件与暂定结论 | 降低堆叠，以结构提示、表情和主动留白保持交流感 |

能力策划器使用 `config/capability-usage/xingzhe.json` 的 `showProfiles` 计算
栏目配额，不能再把工具演示的强效果密度强制套进读书或纪录内容。

## 5. 封面系统

人物是信任锚点，不是封面背景：

- 默认人物高度约为封面高度 38%–44%；
- 合理范围 32%–48%，人物宽度约 22%–30%；
- 默认置于右下或与标题相反的一侧，保留头顶、眼镜、肩部和必要手势；
- 标题区域最大约占封面宽度 56%，标题、栏目、期号各自有独立安全框；
- 主视觉优先采用“人物 + 内容证据/概念图形”，不只剩人物和大字；
- 品牌暖橙承担识别，珊瑚或蓝色只承担本期核心冲突/概念；
- 横版、竖版分别重排，不机械裁切。

五栏目正式封面的人物统一使用原创的高品质院线级 3D 动画电影语言。用户口语
可称“皮克斯风格”，但执行只取其温暖、圆润、可夸张和电影级完成度，不复制
或近似 Pixar、Disney 或其他具体角色、影片造型、Logo 与 IP。人物必须保留
大灰本人可识别的成年脸型、真实年龄感、黑框矩形眼镜、短刺黑发和深藏蓝
运动服；皮肤、头发、眼镜和布料具有精细材质，使用电影级主光与轮廓光。

3D 人物不能把整张封面带成普通动画海报。背景继续使用高密度语义编辑拼贴，
以三至五个同主关系碎片、前中后景、至少两层遮挡、尺度反差和纸张/油墨/网点
印刷质感承载证据与阶段；至少一项主题元素位于人物前景、一项位于人物后景。
工具分享、解读好书、有限的无限游戏、灰常AI和闲聊分别调整任务感、沉静度、动作
重量、反应强度和成年交流感，但共享同一身份、服装和原创 IP 边界。

## 6. 人物后文字与高影响效果

人物后文字必须满足：

1. 文案是章节题眼、记忆点或逻辑落点，不是普通字幕；默认只承载 2–4 个汉字的核心词，最长不超过 7 个汉字；
2. 字号至少为普通字幕的 1.8 倍；
3. 每个字的可读面积不低于 85%，人物遮挡只允许触碰字形边缘，不能压住字心；
4. 默认使用 `signalWarm`；三组并列关系可在中间一组使用理性蓝；
5. 进入按短语分批，不整句同时炸出；
6. 峰值停稳后，在下一主画面或字幕前完整退出；
7. 只配一个与落位同步的功能性 SFX。

完整结论、解释句或两行以上文案不使用人物后文字。竖版优先放在人物头顶上方，
与发顶保留约 0.4–0.8 个字高的呼吸距离；需要视差时只让短词边缘与头发轻微重叠。
横版同样优先使用头顶或视线反方向的负空间，不把长句横跨人物头脸。
两个字分置人物左右时，字间净空至少接近头部可见宽度；不能为了“藏在人物后面”
让两个字同时被头部大面积挡住。

## 7. 参考效果图合同

完整图库由设计系统自动生成：

```bash
node scripts/kacha.mjs design gallery \
  --output design/reference-gallery/xingzhe-v2 \
  --overwrite
```

当前覆盖：

- 52 个组件；
- 69 个场景；
- 8 个渲染器；
- 36 个布局；
- 75 个动效；
- 合计 240 张独立 SVG 参考图。

`index.html` 提供分类和搜索，`manifest.json` 记录当前设计摘要和每张图的
SHA-256。策划、设计预检、正式渲染和返工必须引用同一设计摘要；参考图失效时
重新生成。参考图用于对齐构图、层级和运动意图，不替代真实人像、字幕测宽、
人物蒙版和正常速度视频验收。

对人物后文字、打字回复、分屏、流程图、前后对比、界面聚焦等高影响场景，
还必须提供横版与竖版各一张高保真峰值帧。两种画幅应分别构图，不能把横版机械
裁成竖版。峰值帧只说明效果停稳时“长什么样”，不得作为静态贴图直接铺进成片。
每个高保真样板必须同时携带可执行的动效合同：

- `entry`：从哪里进入、分几拍建立、是否需要人物蒙版或局部遮挡；
- `hold`：停稳时长、可读面积、局部呼吸或镜头运动；
- `exit`：必须在下一段主画面、字幕或口播落点前完整退出；
- `sfx`：声音功能、落点和相对人声/BGM 的层级。

动效合同还必须区分：

- `invariants`：人物、字幕、局部更新、退场和无闪屏等不可破坏条件；
- `parameters`：节点数、标签、尺寸、透明度、路径、速度、景深、粒子和颜色等
  可调参数及其范围；
- `adaptationRules`：人物位置、横竖画幅、语速、信息密度和长文本下的重排与回退；
- `audioContract`：每类声音的功能、视觉峰值、增益起点、次数上限和禁用条件；
- `qualityGates`：正常速度预览、关键帧顺序、碰撞、对比度和完整退场。

高保真样板目前提供五套并列风格：

1. `xingzhe-spatial-lightpath`：空间光路，适合 AI、工具、技术流程和空间关系；
2. `xingzhe-light-overlay`：浅暖轻浮层，适合知识、方法、清单与亲和叙述；
3. `xingzhe-humor-comic`：幽默漫画，适合真实反差、预期落差、误会、尺度错位、反应和回扣；
4. `xingzhe-pixel-editorial`：像素风，适合 AI、工具、规则、计数、状态变化和可量化流程。
5. `xingzhe-dark-tech`：暗黑科技风，适合异常、风险、冲突证据、隐性机制、真伪核验和系统边界。

选择由内容气质、负空间和人物位置决定，不把任何一套设为全局硬编码默认。

五套风格的共同字体与布局合同由
`config/design-system/visual-languages.json` 与 `config/font-routing.json` 统一约束：

- 常规字幕使用真实金陵体，不加底色和描边，阴影不透明度固定为 60%；
- 视频标题、术语定义、金句引用和大号题眼使用华光标题黑，可使用受控透明渐变；
- 封面主标题使用封神榜书，其他封面文字使用细体；
- 栏目、期号、系列、来源和辅助说明使用细体；不得静默回退到其他字体；
- 文字与卡片在渲染前必须输入人物/头部边界、字幕安全区、平台 UI、常驻品牌区、
  局部亮度图和真实文字度量，候选位置评分后再决定字号、颜色、行数和卡片尺寸；
- 常驻品牌模块必须可读，但不得高于主标题 32% 的视觉显著度。

五套风格共用一条声画时间轴合同：口播是主时钟，视觉峰值和功能性音效必须落在
同一语义锚点前后 2 帧内；常规字幕禁止配音效，每个语义拍最多一个主音效，并从
项目 `kacha-profile.json` 按已命名叙事触发解析。发生冲突时依次保护人声清晰度、
人物与证据、字幕可读性、主运动、常驻品牌，装饰层最先降级或删除。参考图、动画、
音效、语音和原片不得分别独立决定节奏。

`workflow-light-overlay` 继承 `设计参考/行者风高保真样板/index.html` 已批准的
非对称编辑式版面、头部负空间、小体积逐项卡片、双层画中画边框和无底板逻辑字幕。
单张浮层默认不超过画面 34%，所有浮层合计默认不超过 46%，禁止大面积不透明白色网页卡。

`workflow-spatial-nodes` 必须保留同一张实拍底图，不允许全屏或矩形黑色遮罩。空间感由
无可见边界的局部径向景深场、深中性半透明玻璃节点、蓝色关系曲线、橙红结论光路和少量粒子建立。
动态时必须先生长路径再落位节点，只让当前节点轻微呼吸，禁止所有节点同时弹出。

`xingzhe-humor-comic` 是成人编辑漫画，不是儿童卡通或表情包墙。它保留实拍人物
和事实证据，只在局部增加墨线轮廓、最多三格分镜、覆盖率不超过 18% 的网点、
反应裁切和不超过 12 个汉字的短气泡。运动以 2–4 帧预备、4–8 帧动作和 4–6 帧
停稳构成，只在真实笑点上允许 103%–108% 的一次性 overshoot；每个语义拍最多
一个 punchline，禁止循环抖动、罐头笑声和无叙事夸张。

`xingzhe-pixel-editorial` 是编辑式像素图形，不是整片低清或游戏 HUD。人物、证据
和所有可读文字保持原清晰度，只让图形层在 1080p 使用 6–12 px 基础网格、最多
8 个强调色、整数硬边和每步 2–4 帧的量化运动。稳定状态必须静止，通常 2–3 步
完成一次变化；禁止持续扫描线、故障闪烁、复古音乐循环和无状态意义的金币/报错音。

`xingzhe-dark-tech` 是取证式揭示，不是黑底赛博 HUD。先保留正常曝光，再局部隔离
一个异常、锁定至多两层证据并落一次裁决；暗场覆盖不超过 42%，人物亮度至少保留
82%，证据至少保留 90%。禁止整屏黑化、霓虹网格、数据雨、连续扫描、随机 glitch
和科幻环境声床。

上述五套风格已扩展到全部 240 个注册效果，不只覆盖流程图。每套均有横版和
竖版独立峰值帧，合计 2400 张；每个“效果 × 风格”组合都有一份 seek-safe
可执行合同，合计 1200 份。合同包含叙事触发、帧级时序、可调参数范围、人物和
字幕适配、音效层级、低能力回退与质量门禁。使用前运行
`kacha contracts validate`，选定效果后再运行 `contracts resolve`，不得只看图
手工猜动画。

五套全量高保真图库交付前还必须执行：

```bash
node scripts/kacha.mjs design library-qc \
  --light /path/to/全量效果库_v3_浅暖轻浮层 \
  --spatial /path/to/全量效果库_v3_空间光路 \
  --comic /path/to/全量效果库_v4_幽默漫画 \
  --pixel /path/to/全量效果库_v4_像素风 \
  --dark /path/to/全量效果库_v5_暗黑科技风 \
  --contracts config/effects/motion-contracts/design-effect-library-v3.json \
  --output /path/to/five-style-qc-report.json
```

该门禁验证 240 个效果、2400 张横竖参考图、真实金陵体文件哈希、60% 字幕阴影、
人物头部碰撞、文字对比度、空间光路近黑区域、漫画/像素材质边界、素材重复、
同风格未声明近似构图和 1200 份独立动效核心。同风格近似构图必须为 0，否则直接
失败；当前通过证据见 `docs/generated/five-style-library-qc.json`。参考图使用显式字体 SVG，经 Chrome 或 `rsvg-convert` 生成；
合同必须如实记录实际渲染路径，不能宣称未使用的 Pillow 渲染器。图库与合同清单
不得写入构建时间戳，同一输入重复构建的 digest 必须一致。

正式实现至少输出一次正常速度短预览，验证进入、停稳、退出和声音同步。只有
峰值帧、没有时间行为，或把静态效果突然切入/切出，均视为未完成。

## 8. 完成门禁

- 设计系统、生产台、效果模板和栏目能力策略均通过验证；
- 全部注册项都有参考图，数量与注册表完全一致；
- `design library-qc` 对五套全量图库和动效合同返回 `pass`；
- 五套库的 `nearDuplicatePairCount`、`headCollisionAssetCount`、
  `spatialBlackAssetCount` 和 `exactDuplicateAssets` 均为 0；
- `design qc --matrix` 覆盖所有模式、组件状态和场景状态；
- 封面人物占比在合同范围，标题和人物不碰撞；
- 亮底字幕使用深色变体；
- 强效果使用语义色，普通信息仍保持中性；
- 运动和音效有明确叙事理由；
- 真实成片仍需正常速度逐段审看，参考图与自动 QC 不等于可发布。
