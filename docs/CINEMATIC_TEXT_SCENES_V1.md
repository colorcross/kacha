# 行者大灰动态字景设计与生产规范 V1.0

## 1. 设计结论

“行者大灰”的屏幕文字采用“阅读字幕 + 语义字景 + 空间字景”三级系统。文字不是统一悬浮在底部的外挂字幕，而是与人物、物体、景别、负空间和镜头运动共同构图的设计图层。

本规范吸收海报式动态文字的尺度、非对称、前后景和硬切语言，但不复制《李白》参考方案的宋体、宣纸、朱砂或古典语汇。行者大灰的核心气质是极简科技、真实、克制、有判断，因此：

- 连续口播仍以准确、单行和稳定为第一优先级；
- 只有真实语义关系才升级为设计字景；
- 大字、引语、术语和注释各自承担不同信息职责；
- 人物遮挡只在逐帧蒙版有效时使用；
- 动效强调“切入、显影、落稳和退出”，不弹跳、不拖尾、不整行卡拉 OK 变色；
- 任何视觉包装都不能掩盖错字、错轴、错引语或不完整表达。

## 2. 三级信息架构

| 层级 | 作用 | 典型内容 | 建议密度 | 默认音效 |
| --- | --- | --- | --- | --- |
| 阅读字幕 `reading` | 连续理解口播 | 事实、解释、过渡 | 可覆盖全片 | 无 |
| 语义字景 `semantic` | 显示真实信息关系 | 对照、定义、数字、引语、结论 | 不高于全部 cue 的 28% | 只在可见落点使用 |
| 空间字景 `spatial` | 建立人物前后景和章节记忆点 | 1–4 字题眼、前后景短语 | 不高于全部 cue 的 10% | 极少量使用 |

连续语义字景最多两条，连续空间字景最多一条。超过建议密度时，计划会给出警告；生产交付使用 `--strict-text-scenes` 时直接阻断。

同一时刻最多三个阅读区、一个主强调。设计字景结束后必须回到安静的阅读基线，让画面重新获得呼吸。

## 3. 字体与字体质感

### 3.1 字体职责

1. 常规阅读：`方正粗金陵简体 / FZJinLS-B-GB`。
2. 展示题眼、术语、引语：`青鸟华光标题黑体 / JBHGBTH`。
3. 来源、栏目、参数和辅助注释：`思源黑体 CN Light`。

字体文件必须来自本项目授权注册表。字体二进制保持私有，不进入公开仓库。缺字、缺文件或哈希漂移必须阻断，禁止静默替换成相似字体。

### 3.2 质感规则

- 不使用厚描边和卡拉 OK 外发光；
- 阅读字幕无底板，使用 60% 接触阴影；
- 展示字阴影降低至 38%，保留字面边缘和视频质感；
- 回声字透明度默认为 11%，只承担构图和景深，不承担阅读；
- 图形强调面积不超过字景构图的 8%；
- 可用轻微胶片颗粒、扫描纹理或透明梯度，但不能降低笔画识别度；
- 一帧最多一个展示字体和一个正文/辅助字体。

### 3.3 字号比例

以下比例按画面高度计算，横竖屏保持比例后再做手机端验收：

| 角色 | 横屏建议 | 竖屏建议 | 约束 |
| --- | --- | --- | --- |
| 阅读字幕 | 5.0%–5.5% | 3.8%–4.5% | 单阅读区单行 |
| 主题眼 | 7.8%–9.0% | 6.8%–8.2% | 一般不超过 8 字 |
| 背景回声字 | 17%–23% | 14%–20% | 1–4 字、低透明度 |
| 辅助注释 | 4.0%–4.4% | 2.6%–3.0% | 手机端必须可读 |
| 来源署名 | 4.0%–4.4% | 2.4%–2.8% | 不抢引语正文 |

## 4. 五个栏目的统一骨架与差异

五个栏目共用相同字体、无描边、无底板、安全区和密度规则，只改变副色、图形母题和运动性格。

| 栏目 | 副色 | 图形母题 | 运动性格 | 典型应用 |
| --- | --- | --- | --- | --- |
| 工具分享 | `#55C7E8` 冷青 | 精密刻度、短规则线 | 准确、快速落稳 | 参数、步骤、效率判断 |
| 解读好书 | `#D2AE72` 暖金 | 编辑引号、短书脊线 | 克制、稍长停留 | 原句、出处、概念 |
| 有限的无限游戏 | `#9887D8` 灰紫 | 开放地平线、远点 | 展开、留白 | 命题、边界、选择 |
| 灰常AI | `#62D9B0` 薄荷绿 | 数据括号、节点 | 技术、清晰 | 模型、算法、定义 |
| 闲聊 | `#E89A72` 暖橙 | 松弛角标、小圆点 | 自然、轻巧 | 自嘲、转折、个人判断 |

副色只用于规则线、短注释、微型进度和局部题眼。大面积正文仍由品牌的骨白/墨色承担，以免五个栏目分裂成五套视觉品牌。

## 5. 图形系统

### 5.1 规则线

规则线连接题眼与注释，或建立同一透视轴。线宽约为画面高度的 0.2%–0.3%，先显现、后落字。没有对应信息关系时不画线。

### 5.2 回声字

只从当前句或当前章节抽取 1–4 字。可被画面边缘裁切，透明度 7%–14%。回声字不能新增事实，也不能进入主要阅读区与正文竞争。

### 5.3 栏目图形母题

刻度、引号、地平线、数据括号和松弛角标由渲染器按栏目档案生成。它们不是贴纸，不单独播放，不连续堆叠。

### 5.4 逐字进度

音乐、诗歌或节奏精确的口播可以显式使用 `micro_rail`：以 2–3px 细线表现逐字进度。正文保持稳定颜色，不做整行逐字泛色。启用进度线必须提供单调、位于 cue 内的 `words` 时间；缺少逐字时间时直接阻断。

## 6. 十种可执行布局

现有渲染器注册十种布局：

1. `plain_single`：常规单行，连续阅读基线。
2. `logic_emphasis_inline`：单行内只强调一个判断词。
3. `left_right_contrast`：两个同层级概念左右对照。
4. `side_vertical_labels`：中心主体两侧的极短分类词。
5. `top_bottom_hierarchy`：问题/答案、概念/解释的上下主从。
6. `editorial_stack`：大题眼 + 小解释 + 可选回声字的非对称编辑堆叠。
7. `edge_annotation`：术语或数字贴边，配规则线和短注释。
8. `quote_field`：已核实引语 + 出处 + 可选回声词。
9. `oversize_background_word`：人物后方 1–2 字空间题眼。
10. `front_back_phrase`：背景短语、人物和前景补充共同形成遮挡层次。

前三种设计字景的字段约束如下：

| 布局 | 必填字段 | 字数上限 | 默认回退 |
| --- | --- | --- | --- |
| `editorial_stack` | `primary`, `secondary` | 8 / 16 字；`echo` 4 字 | `top_bottom_hierarchy` |
| `edge_annotation` | `primary`, `annotation` | 8 / 18 字 | `logic_emphasis_inline` |
| `quote_field` | `primary`, `source` | 24 / 14 字 | `top_bottom_hierarchy` |

`quote_field` 没有出处时不允许生成。“看起来像名言”不等于已核实引语。

## 7. 空间融合

- 水平安全区为画宽 7%，顶部 9%，底部避让区 20%；
- 人脸安全距离至少为画面短边的 6%；
- 不遮挡眼睛、嘴部、主要手势、产品关键操作和平台 UI；
- 文字锚点必须服从镜头负空间，不能为了版式把主体挤出视觉中心；
- 允许 0°–1.2° 的轻微旋转和 3–8px 视差，但必须与建筑线、桌面线、屏幕边缘或镜头运动一致；
- `oversize_background_word` 与 `front_back_phrase` 必须使用与当前视频同尺寸、同帧率、同帧数的逐帧人物蒙版；
- 蒙版还必须与源视频保持同一时长和起始 PTS，禁止末帧复制或静默截短；
- 没有蒙版时不得用静态框或单帧抠图伪造前后景。
- 正式字景必须把落点背景显式分类为 `light` 或 `dark`；`footage` 只用于规划和普通阅读，不能在严格交付中代替亮度判断。

## 8. 动效语言

每个高影响文字事件都要有 `entry → visible landing → hold → exit`：

- 入场：通常 2–6 帧内完成方向揭示、规则线展开或 104%→100% 落稳；复杂空间短语最多 12 帧，且 cue 必须留有完整停稳时间；
- 可见落点：不得早于对应语音；音效峰值与落点误差不超过 1–2 帧；
- 句中：保持稳定，不持续漂浮；回声字只做极弱视差；
- 出场：在下一 cue 前完成定向切走或清场；
- 禁止：弹跳、果冻回弹、长拖尾、无意义淡入淡出和持续发光。

栏目只改变运动性格，不改变时间纪律：工具分享更精准，解读好书更克制，有限的无限游戏更展开，灰常AI更技术，闲聊更自然。

## 9. Cue 数据契约

```json
{
  "id": "ai-term-01",
  "start": 12.0,
  "end": 14.2,
  "text": "这个参数决定模型能记住多少上下文",
  "textScene": {
    "show": "灰常AI",
    "layout": "edge_annotation",
    "role": "术语定义",
    "anchor": "right",
    "progressMode": "none"
  },
  "display": {
    "primary": "上下文窗口",
    "annotation": "一次推理可读取的信息范围"
  }
}
```

音乐或逐字节奏示例：

```json
{
  "id": "lyric-01",
  "start": 20.0,
  "end": 21.2,
  "text": "让每一个判断落在画面里",
  "textScene": {
    "show": "闲聊",
    "layout": "plain_single",
    "progressMode": "micro_rail"
  },
  "words": [
    { "text": "让每一个判断", "start": 20.0, "end": 20.65 },
    { "text": "落在", "start": 20.65, "end": 20.9 },
    { "text": "画面里", "start": 20.9, "end": 21.2 }
  ]
}
```

## 10. 生产命令

先生成可审计计划：

```bash
node scripts/kacha.mjs captions plan \
  --input /absolute/input.mp4 \
  --transcript /absolute/cues.json \
  --mask /absolute/person-mask.mov \
  --show 灰常AI \
  --surface dark \
  --output /absolute/caption-plan.json
```

严格检查字景密度、字体、蒙版、逐字时间和素材身份：

```bash
node scripts/kacha.mjs captions validate \
  --plan /absolute/caption-plan.json \
  --strict-text-scenes
```

渲染：

```bash
node scripts/kacha.mjs captions render \
  --plan /absolute/caption-plan.json \
  --output /absolute/captioned.mp4
```

完整示例见 `examples/cinematic-text-scene-cues.json`。该文件为了集中展示五个栏目而有意提高字景密度，不代表正式成片密度；正式项目必须在完整转写上运行严格检查。

## 11. 生成流程

1. 锁定真实音频、文字和逐句/逐字时间，不重新改写已确认台词。
2. 按语义标记普通叙述、判断、对照、定义、引语、章节题眼和空间题眼。
3. 默认生成 `plain_single`；只有关系明确且字段齐全时显式升级布局。
4. 选择栏目档案、明暗表面和左右锚点。
5. 路由真实授权字体，并写入文件 SHA-256。
6. 对空间字景校验逐帧蒙版；缺失时阻断或降级。
7. 生成计划、密度评估、回退记录和 digest。
8. 渲染透明前景/背景文字层，再与人物蒙版、原视频和音频合成。
9. 运行全片解码、几何、时长、字体、蒙版和音效峰值检查。
10. 用手机尺寸、正常倍速人工看完全片，复核错字、遮挡、节奏、风格一致性和信息密度。

## 12. 验收门槛

自动验收：

- 每个 cue 有有效、单调、不重叠的时间区间；
- 逐字时间位于 cue 内且单调；
- 输入、转写、字体注册表、字体文件和蒙版 SHA-256 未漂移；
- 源视频与蒙版的尺寸、帧率、时长、帧数和起始 PTS 完全对齐；
- 每个事件可由冻结转写、栏目档案、布局/字体路由注册表和设计系统重新构建；
- 字数和必填字段符合布局约束；
- 空间字景只有在有效蒙版存在时使用；
- 普通字幕无逐卡音效；
- 输出完整可解码，分辨率、帧率和时长保持源视频；
- 严格模式下字景密度不过量。
- 严格模式下所有字景使用正式栏目、显式亮/暗表面和真实项目授权字体，不允许系统字体回退。

人工验收：

- 正常倍速看完整片，不只抽帧；
- 手机尺寸能读清正文和辅助小字；
- 人脸、嘴部、手势、产品操作和平台按钮未被遮挡；
- 大字确实服务当前命题，而不是装饰；
- 运动落点与语音/音乐一致，没有提前“剧透”或延迟拖沓；
- 五个栏目能被感知但仍属于同一个“行者大灰”品牌；
- 引语、数字、术语和来源经过内容校准。

自动通过只代表技术门禁通过，不能替代正常倍速的人眼审美与内容验收。
