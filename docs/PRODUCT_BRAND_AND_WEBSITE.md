# 咔嚓产品品牌与官网设计规范

本规范定义咔嚓（Kacha）作为独立工具产品的品牌表达、官网视觉、文案、组件、
动效和维护边界。它服务于官网、GitHub、文档、社交分享图和未来产品界面，
不替代 `docs/VIDEO_DESIGN_SYSTEM_V1.md` 中用于成片的“视频设计系统”。

正式官网：

- 中文：<https://colorcross.github.io/kacha/>
- 英文：<https://colorcross.github.io/kacha/en/>

## 1. 品牌定位

**产品类别：** 本地专业 AI 视频工作流 skill。

**核心价值：** 把策划、精剪、声音、画面、字幕、增量返工和质量检查组织成
可审计、可复现、失败即停的流程。

**品牌承诺：** 不把预览冒充成片，不把自动检查冒充人工审片，不把 AI 能力
包装成“一键魔法”。

推荐主文案：

> 不只会加效果。把视频工作流做完。

推荐英文：

> More than effects. Finish the workflow.

产品署名使用“由行者大灰构建 / Built by 行者大灰”。“咔嚓”是工具品牌，
不是新的内容栏目；对外内容仍遵守项目当前四栏目体系和独立期号规则。

## 2. Logo

主 Logo 位于 `assets/brand/kacha-logo.png`。图形由三个语义组成：

1. 剪刀：选择、删减和精剪；
2. 播放/字母 K 的几何关系：视频工作流与 Kacha；
3. 橙色切点：当前动作、关键落点和可验证状态。

使用规则：

- 只使用仓库中的主文件，不重新描摹、不改变各几何元素比例；
- Logo 四周至少保留“橙色圆点直径的 2 倍”作为安全留白；
- 正方形载体最小显示尺寸为 32 px；小于 48 px 时不附加文字；
- 暖白或纯白背景为默认；深色背景必须使用独立验证过的反白版本，当前版本
  未提供反白文件，不允许通过 CSS 直接反色；
- 不加外发光、立体挤压、霓虹描边或与橙色圆点竞争的装饰；
- 原图包含较大留白。网页可通过容器裁切和等比缩放改善显示，但不得修改
  图形本体。

## 3. 色彩

色彩从用户提供的 Logo 像素采样，并建立语义角色：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `paper` | `#F5F2EB` | 主背景、暖白信息面 |
| `paper-bright` | `#FCFBF8` | 高亮表面、卡片 |
| `ink` | `#24272F` | 主文字、深色按钮、页脚 |
| `graphite` | `#41454E` | Logo 主体近似色、次级文字 |
| `steel` | `#727985` | 标签、说明、辅助刻度 |
| `line` | `#D9D4CA` | 分隔线、边框 |
| `signal` | `#FB6B14` | Logo 橙点平均色、主动作 |
| `signal-red` | `#F42800` | 橙点深端，仅用于小面积渐变 |
| `signal-gold` | `#FEAE5F` | 橙点亮端、通过状态强调 |
| `night` | `#191B21` | 时间线、终端和技术表面 |
| `positive` | `#79D18A` | 已验证、通过、在线状态 |

规则：

- 橙色是“动作和切点”，不是大面积背景色；单屏建议不超过 12%；
- 不使用紫色科技渐变、蓝紫霓虹或大面积高饱和 AI 风格；
- `positive` 只表示真实通过状态，不能用于装饰；
- 正文与背景至少满足 WCAG AA 对比度；亮底不用白字，暗底不用深字；
- 视频栏目自己的色板由视频设计系统管理，不能从官网色板直接覆盖。

## 4. 字体与排版

显示字体优先：

```text
Avenir Next Condensed / DIN Condensed / Arial Narrow
PingFang SC / Noto Sans SC
```

正文字体优先：

```text
Avenir Next / SF Pro Display
PingFang SC / Noto Sans SC / system-ui
```

数据、命令和状态使用等宽字体：

```text
SFMono-Regular / Roboto Mono / Cascadia Code / monospace
```

排版规则：

- 标题使用收窄字面、大字号、紧字距，正文保持充足行距；
- 中文不机械插入全角空格；英文标签使用大写和较大字距；
- 主标题只强调一个语义短语，橙色不超过一行；
- 长文正文每行 28–42 个中文字符或 55–75 个英文字符；
- 数字指标与解释分层，不能只展示大数字而缺少口径。

## 5. 栅格、形状与图形语言

- 桌面内容最大宽度 1420–1520 px；
- 使用 12 列概念栅格，主要模块遵循 1:1、3:2、2:1 等明确比例；
- 基础间距为 4 px，常用层级为 8 / 12 / 20 / 32 / 48 / 80 / 128；
- 圆角保持克制：按钮和卡片 2–4 px，只有状态点与 Logo 容器可用圆形；
- 斜向切线来自剪刀动作，只在章节转场、主视觉和时间线落点使用；
- 视频时间线、波形、播放头、QC 节点是产品专属辅助图形；
- 不使用无语义的玻璃拟态、漂浮球、随机渐变光斑或通用 AI 星芒。

## 6. 官网组件

当前官网位于 `website/`，核心组件包括：

| 组件 | 叙事职责 |
| --- | --- |
| 品牌锁定 | Logo、KACHA、咔嚓，建立双语识别 |
| 浮动章节导航 | 长页面中持续保留痛点、效果、风格、流程、安装与联系入口；移动端改为可横向浏览的紧凑章节条 |
| Hero 时间线 | 以轨道、波形和 QC 节点说明产品是工作流 |
| 证据条 | 展示当前版本组件、场景、检查和任务路径口径 |
| 能力卡 | 解释系统能力，避免堆功能名 |
| 能力 Bento | 用主能力、常规能力和全宽收束能力形成不同阅读权重，避免同尺寸卡片连续堆叠 |
| 流程列表 | 从策划到质量门禁逐步收束 |
| 原则宣言 | 明确本地、默认关闭、真实边界 |
| Beauty 状态 | 用 `OFF` 直接表达默认关闭 |
| 安装终端 | 提供真实可复制命令和依赖提示 |
| 五种剪辑语法 | 用五种不同空间与时间构图解释浅暖、空间、漫画、像素和暗黑科技；不做同卡换色 |

组件新增必须回答：

1. 它解决哪个信息问题；
2. 为什么现有组件不能表达；
3. 它在手机上如何重新流动；
4. 它是否引入新的状态或授权误解。

## 7. 动效

动效来自剪辑动作，而不是网页装饰：

- Logo 橙点：2.8 秒低频呼吸，表达当前切点；
- 导航下划线：180 ms，从动作方向进入；
- 卡片悬停：最多上移 8 px，不旋转、不弹跳；
- 时间线播放头：保持静态或低频移动，不能制造“正在处理”的假状态；
- 内容进入：只在真实滚动触发时使用 180–420 ms 的淡入/位移；
- 五种语法示意：浅暖仅做边缘旁注呼吸，空间只移动路线，漫画保持定格分格，
  像素光标按离散状态闪烁，暗黑科技只做局部证据锁定与一次裁决；五者不能共享同一连续动画；
- `prefers-reduced-motion` 下停用非必要动画。

禁止使用整屏闪烁、连续粒子、无限旋转、无目的视差和盖住内容的光效。

## 8. 文案与证据

文案遵守四条：

1. 先说能解决的真实任务，再说技术；
2. 明确区分计划、渲染、技术通过、人工审片和发布；
3. 能力数字带“当前版本”口径，并在变更后同步；
4. 明确列出默认不上传、默认不美颜和不夸大。

不能使用：

- “一键生成专业大片”；
- “完全替代剪辑师”；
- “100% 自动、零人工”；
- “行业最强”等无法核实的比较级。

## 9. 响应式与无障碍

- 1100 px 以下把主导航改为紧凑的横向章节条，760 px 以下内容转为单列；
- 触控目标不小于 38×38 px，主要按钮不小于 44 px 高；
- 所有交互支持键盘焦点；
- 页面提供跳过导航入口，固定导航不能遮住章节锚点；
- Logo 装饰图使用空 `alt`，品牌链接本身提供可读名称；
- 颜色不是唯一状态线索；通过状态同时使用文字、图形和颜色；
- 安装命令可横向滚动或自动换行，不能溢出屏幕；
- 中英文页面分别提供正确语言与完整内容，不做逐条机器直译占位。

发布前必须：

1. 运行官网 lint、typecheck、构建、服务端渲染测试和 Pages 子路径测试；
2. 检查中文与英文首页；
3. 运行仓库回归测试、安装器测试和隐私扫描；
4. 校对 README 中的能力数字与官网一致；
5. 复核 Logo 和社交分享图没有文字错误、遮挡或授权问题；
6. 检查 GitHub Pages workflow 成功、正式 URL 返回 200 且资源无 404；
7. 核对仓库 About 的 Website 指向正式官网。
