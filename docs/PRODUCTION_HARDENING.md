# 生产流程加固

本文件把真实制作中反复出现的缺陷转成流程门禁。目标不是增加效果数量，而是让内容、画面、声音和版本证据始终属于同一条时间线。

## 新增默认门禁：人声、系列和原画幅

- 含口播的整支剪辑不能绕过真实源分离：`dialogueAudio.sourceSeparation` 必须明确最终人声来源、原始参考、residual 审计和 residual 禁止回混。
- 系列身份在 inventory 阶段确定；执行方案不得保留 `undetermined`。检测到系列时，视频和封面标识缺一不可。
- 用户没有明确要求改变视频尺寸或宽高比时，输出几何必须与源探测值一致；封面规格和平台习惯不能触发自动改画幅。
- 每次修改 Skill 后，先同步 Codex/ChatGPT 与 Claude Code 安装并运行一致性测试，再报告优化完成。
- 每次出片后只评估中间产物，不自动删除；例行清理要求用户不需要、快速可重建且不影响返工，最终清理要求用户明确确认不再修改。
- 用户/项目配置可提供参数和自然语言默认要求，但不能代替当前项目的上传、
  付费、发布、覆盖或门禁授权；密钥与公开配置必须物理分离。

## 1. 创意锁定

在粗剪或生成素材之前，先在 `editProposal.creativeLock` 锁定：

- 源画幅与输出画幅；
- 是否保持源容器、编码、分辨率、帧率与色彩；
- 谁是前台叙事主体；
- AI 是前台角色、画外回应还是只在背后执行；
- 哪些决定冻结；
- 任何偏离都必须重新获得授权。

未经重新确认，不能把横屏改成竖屏，不能把幕后 AI 改成前台角色，也不能用新的视觉概念替换用户明确给出的表达。

## 2. 内容先于效果

顺序固定为：

1. 盘点源文件与真实规格；
2. 以音频为主完成转写和语义校准；
3. 先删完整口误、废话和无意义停顿；
4. 逐连接点核验完整句、音画共边界与自然强弱；
5. 冻结精剪时间线；
6. 再安排景别、插镜、动效、字幕、BGM 和 SFX。

效果不能参与掩盖错误切点。任何删除区间都必须来自词级时间戳，并让 visual、dialogue、BGM、SFX、subtitles 使用同一组帧边界。

## 3. 效果最小合同

每个效果必须回答：

- `trigger`：由哪条信息、情绪、视角或可见动作触发；
- `mechanism`：为什么这种表现能帮助理解或连续性；
- `entryExit`：从哪一帧进入、停留多久、在哪一帧前退出；
- `simplerAlternative`：更简单的做法是什么；
- `failureCondition`：什么现象出现时立即回退；
- `qcEvidence`：用什么代表帧、短预览或试听证明通过。

专项要求：

- 打字：逐字符落位；可见字符帧与精确音效事件绑定；
- 画中画：定义边框/圆角/阴影，检查进入前、停留中、退出后；
- 分屏：每个主体单独设置头顶、脸、手势和字幕安全区；
- 信息卡/流程图/弹窗：只允许全屏替换 A-roll，或使用几何验证过的头像安全布局；装饰和阴影也计入模块边界；
- 插镜：核对对象、动作、状态、角色、时态，切回主画面前 1–4 帧完成退出；
- AI 生成镜头：入口姿态、出口姿态、运动方向和人物外观必须连续；
- 2.5D：先验收分层、alpha、PTS、首中尾帧和短预览；出现黑帧、空洞、拉伸或漂移即回退为普通推拉或静态插镜；
- 切镜：信息、情绪或视角至少变化一项；同一主体相邻镜头必须有可感知的景别变化；每个切点填写切法、连续性依据、声音处理、备选和预览证据；
- 人物构图：普通人物镜头切前、切后都保留完整头发和头顶余量；只有明确设计的特写/大特写允许裁切头部；
- 人物后文字：字体、字号比例、位置、颜色、对比度、可见面积、分组和 SFX 同步全部进入效果合同；
- 设计预检：信息卡、流程图、弹窗、风格化转场、人物后文字和其他蒙版必须先冻结本地样式帧或 Figma 设计、三态动效和声音交接，再实施。
- 多状态点亮：流程图、音频清理和逐项完成模块必须保持底图稳定，只更新当前节点；状态之间禁止整屏 alpha fade、闪白或全图亮度跳变，并以边界差分帧验收。

## 4. 人物安全布局、设计与转场门禁

在 `fine_cut` 和 `visual_packaging` 之间增加三项预检：

1. `head-integrity pass`：逐切点导出切前 1 帧和切后 1 帧；有人且不是有意特写时，头发完整、头顶余量至少约画面高度 1.5%。
2. `layout-collision pass`：信息卡、流程图、弹窗和人物后文字导出信息最满的代表帧；检查头像、字幕、品牌和平台 UI 边界。
3. `design-preflight pass`：核对 `entry / peak / exit` 样式帧、布局、动效、声音、实现交接和批准证据；复杂多状态/多画幅模块可由 Figma 产出，但没有 Figma 时必须用本地样式帧完成同等预检。

切法按“语义/主体变化 → 干净切或 J/L-cut；动作延续 → 动作/匹配切；固定机位删段 → 景别变化或插镜；真实章节、时间、空间变化 → 有 handle 的转场”选择。风格化转场必须先和干净切做 A/B；不能明显改善理解、情绪或连续性时，回退干净切。

结构删除完成后，从最终拼接时间线重新检测全部连接点并生成 `connectionAudit`。
检测数必须等于 cutSheet 数，逐点在正常速度下检查前后 handle；同景别姿态跳变、
双切点、短残片、音量跳变或无声模板转场都属于未解决连接，不能进入最终渲染。

## 5. 原创音效精确选择

用户点名音效时禁止凭听感替换：

1. 通过 title 或 asset ID 唯一命中；
2. 核对原始与 48 kHz 工作副本 SHA-256；
3. 核对实际时长、采样率和声道；
4. 按动作或字符真实落位帧布置；
5. 正常速度在手机扬声器和耳机试听。

仓库只内置 12 个经作者确认的原创音效。第三方库存音效即使可用于成片，也不得作为素材包随仓库再分发。

精确命中之后还要做整片审计：4 个及以上 SFX 事件至少使用 3 个不同音效，单个音效占比不超过 50%，同一音效不连续超过两次；逐字打字等连续动作例外必须在 `sfxPlan.events` 写明。检查发现信息卡、转场、文字落位和结论全部使用同一声音时，必须退回选音，不能靠调音量伪装差异。

## 6. 美颜能力门禁

美颜默认关闭。明确启用后，公开 core 只允许本地 Beauty v2，作用域限定为
磨皮、美白、匀肤和法令纹弱化。项目必须记录 Beauty v2 版本、参数 profile、
皮肤/法令纹蒙版、输入/输出几何和失败策略。不得回退 GPUPixel、云端美颜、
生成式人脸修复、全局模糊或改变脸型的算法。

无论使用哪个后端，都必须：

1. 先做短片段和同源、同帧、同裁切、同尺寸 A/B；
2. 检查正脸、转头、说话、眨眼、反光、遮挡和多人误检；
3. 检查脸、颈、耳、手臂质感连续，眼睛、眉毛、嘴唇、眼镜和背景不过度变软；
4. 检查脸型变化、纹理保留、闪烁、漂移和帧数/时长不变；
5. Beauty v2 不可用或专项 QC 失败时停止，不得静默换成另一算法并声称等效。
6. Beauty 渲染命令必须通过项目级 `enabled=true` 授权并携带逐帧 Vision
   manifest；默认配置、仅传 profile 或直接调用脚本都不能绕过默认关闭。
7. 主脸覆盖、关键点覆盖、多人歧义率、跟踪跳变、Y/U/V 遮罩隔离和媒体
   保真先做自动门禁；正脸、说话、转头、眨眼、眼镜反光和手靠近脸部仍需
   同源同帧人工动态复核。
8. 技术报告必须同时冻结配置 digest 与实现链 digest；算法文件变化后，旧
   报告不能作为新实现的发布证据。
9. Vision manifest 必须绑定源视频 SHA-256；人工复核记录必须绑定当前输出、
   当前 Vision manifest、profile、复核人和复核时间，不能复用其他版本记录。

## 7. 局部修改与版本冻结

每轮局部反馈使用 v3 `version-delta.json`，不再复制整套 v2 方案。稳定事实进入
`project-context.json`，可复用产物进入 `artifact-index.json`；脚本自动推导
冻结层、影响级别、失效依赖、渲染策略和动态 QC。

- 纯声音变化 stream-copy 原视频流；
- 纯画面变化保留原音频 elementary stream；
- 封面专项版本不渲染视频；
- 删除、重排、改时长或改几何升级为 L3；
- 字幕和临时元素在连接点前 1–4 帧退出；
- 缓存必须匹配内容指纹和依赖，显式请求也不能绕过失效规则；
- `candidate` 只做返工验收，`release_candidate` 才做完整发布验收。

修一处同类问题后，对全片同类位置做规则化回归。旧审片结论只有在对应冻结
流哈希与依赖身份不变时才能继承；旧报告本身不能复制。

## 8. MOV 与帧率

“保持原格式”要分别核对容器、视频编码、音频编码、尺寸、declared FPS、average FPS 和色彩元数据。

只修 MOV 时间基时使用 `normalize_mov_timing.mjs` 做 stream-copy 重封装；脚本会在 declared/average FPS、编码或时长不符合合同时删除失败输出。不能为了修 metadata 把整支画面重新编码。

## 9. 结束条件

只有以下证据属于当前输出版本时，才能说“本地 QC 通过”：

- 当前 proposal、edit plan 与 project manifest；
- 当前成片 SHA-256；
- 完整解码、declared/average FPS、A/V 漂移、响度和 true peak；
- 所有连接点、字幕、插镜、蒙版、美颜、声音和封面的人工证据；
- 当前 release report 和 release gate。

旧版本报告、导出完成提示、预览片或局部测试都不能冒充最终交付。

## 10. 中间产物两级清理

1. 先盘点类型、数量、大小、Git 状态、时间线引用和重建成本；
2. `routine` 只允许删除用户不需要且几分钟内可确定性重建的缓存；
3. 蒙版、代理、stem、设计稿或生成素材只要仍影响返工，就继续保留；
4. `final` 必须记录用户明确的“已经完成且不会再修改”原话与时间；
5. 删除目标使用精确相对路径，不接受 glob、项目根目录、主目录或项目外路径；
6. 清理后复核 protected paths、最终视频、封面、工程和 release package。

## 11. 低能力模型与 Claude Code 门禁

- 较弱模型先运行 `prepare --model-tier economy`，只加载 `readOrder`；预算
  超限时拆分阶段/模块，不截断 reference；
- 已有项目每次运行 `next`，只执行一个 `nextAction`；
- 常见增量返工用 `compile-change` 稳定配方，禁止手工漏填变化层和验收条件；
- `nextAction.owner=render_engine` 或 `human` 时，代理不得伪造完成状态；
- Claude Code 涉及画面时必须先生成 `visual-evidence.json/.md`；
- 本地视觉证据不足时，MiniMax 只能分析同时获得外传、付费服务和显式命令
  授权的少量关键帧；上传前复核帧 SHA，不上传整段视频、不自动重试；
- MiniMax/Apple Vision 的单帧结果不能证明转场、口型、蒙版闪烁、美颜时域
  稳定或全片无漏检，仍需动态短片和正常速度通看。

## 12. 英文工具视频返修暴露的系统问题

本轮把以下问题升级为回归门禁：

1. **动效整体抢跑**：不能用统一偏移修所有事件；每个动作绑定实际口播触发词、
   可见动作峰值或信息停稳点，视觉与 SFX 共用帧级 cue。
2. **渐进模块整屏闪烁**：流程图、音频处理和逐项点亮使用持久底图，只更新
   当前节点；状态边界对活动区外做帧差，禁止整帧 PNG 重复 alpha fade。
3. **弹窗遮挡人物**：碰撞检测使用完整模块边界，包含阴影、装饰和动效超调；
   进入、信息最满、退出三态都要对头脸轨迹检查。
4. **亮底字幕失去对比**：style profile 必须同时提供 dark/light surface
   variant；渲染计划标注表面类型，不能靠人工临时换色。
5. **结构连接遗漏**：删除和拼接完成后，从最终时间线重新枚举连接，不以效果
   清单代替连接清单；检测数、审计数和 cutSheet 数一致，未解决项为零。
6. **风格参数散落**：字体、色板、弹窗、卡片、PIP、品牌、封面和运动语言全部
   由统一 style token 提供，项目代码只记录 style digest 和批准偏差。
7. **返工反复重渲染**：自然语言反馈先归一化为稳定配方，同类问题自动扩展到
   全片扫描；样例批准后才渲染失效层，冻结流用 elementary-stream hash 证明。
8. **BGM 技术存在但听感消失或成片漏混**：最终混音保留闪避后的
   dialogue/BGM/SFX 组件 stem 与 mix stem；要求 BGM 的项目在 manifest
   声明 `outputs.audioStems` 与 `expectedMedia.audioMix`。自动 QC 直接测量
   dialogue/BGM 的综合响度差和 BGM 时长覆盖，重建组件混音，并把最终视频
   解码音频与 mix stem 做残差信噪比比对。自适应项目只在计划音乐区间测量，
   默认差值必须在 12–24 dB；音乐过低、
   组件无法重建或成片漏混均阻断交付。
9. **前置验证通过、项目门禁才发现素材不可追溯**：`timeline validate` 对
   final 模式提前要求 proposal/editPlan 合同、source SHA，以及字幕、外部
   画面、dialogue、BGM、SFX 的 SHA 与 provenance；不能把同一错误推迟到
   `gate-plan`。
10. **旋转元数据被当成物理画幅**：探测同时记录 encoded/display geometry，
    ±90° 素材先按显示几何计算构图；最终输出保持显示方向，景别裁切也按显示
    坐标执行。
11. **局部预览仍从源片开头解码**：局部 Render Graph 必须记录最早命中的
    `sourceSeekSeconds` 并在输入前精确 seek；EDL、字幕、BGM、SFX 仍以输出
    区间重新归零，避免为了看十几秒而解码几百秒。
12. **各 stem 合规但最终总线峰值被抬高**：时间线用
    `audio.masterTruePeakDb` 明确母带上限并写入渲染 manifest；默认
    `-4 dBTP`，最终以解码成片实测为准。
13. **转场只写在方案里，渲染仍是硬 concat**：Timeline IR 必须逐边界编译
    `transitions[]`，画面使用实际 xfade/overlap，人声使用同长 acrossfade；
    manifest 固化实际执行数和帧数，计划数与执行数不一致直接失败。
14. **QuickTime 只有声音**：HEVC MP4/MOV 强制 `hvc1`，H.264 使用 `avc1`，
    并启用 fast-start；技术 QC 读取 `codec_tag_string`。不能把能被 FFmpeg
    解码误当成已通过 Apple 播放兼容。
15. **语义音效绑定动画起点导致整体抢跑**：分别记录 `entryStartFrame`、
    `visibleLandingFrame` 和 `sfxPeakFrame`；动画可提前建立运动，但文字在
    触发词前不得完成可读，SFX 只绑定可见落位而不是入场第一帧。
16. **同源 PIP 重复主画面**：普通真人 PIP 先 full-frame fit；细节型 PIP
    只裁手部、物件、界面或证据并记录信息差。主画面与 PIP 展示同一内容时，
    改用景别、虚拟机位、空间重构或移除 PIP。
17. **中文路径下人声分离缓存递归失败**：高成本脚本进入缓存子进程前必须把
    自身路径解析为绝对路径；不得把相对 `${BASH_SOURCE[0]}` 交给会切换 cwd
    的缓存执行器。
18. **效果数量很多但观众几乎看不见**：全流程项目必须提供
    `visualCapabilityPlan`，同时检查能力家族配额、实现多样性、可见时长、
    屏幕占比、字体层级、PIP 信息差、素材来源和 Timeline IR 绑定。小号顶部
    文字、重复颜色标签和轻微裁切不能同时冒充语义动效、纵深、PIP 和字幕关系。
19. **返工比首剪更慢**：L0–L2 禁止 `full_rebuild`；参数探索只做 1–3 个
    代表区间。代表样例批准后，每个版本最多一次整片代理、一次正式编码和
    一次完整 QC。遥测在执行前按 `version-id` 消费预算，超限直接阻断。
20. **短视频或自动导演跳过开场动画**：每条视频无论时长都必须且只能选择
    一个主开场。核心开场与 `z-en-netstyle` 开场共用 Studio 目录；自定义方案
    必须提供完整动效合同。0.5 秒内没有建立可见变化、3 秒内没有兑现内容承诺、
    缺正常速度动态预览或代表帧时，`visualCapabilityPlan` 和 `gate-plan` 阻断。
21. **按固定秒数堆效果或声画互相打架**：语义画面按重点、负面、聚焦、多观点、
    事实、移动和创意七类决策路由；空间变化按蒙版视线、层间插框、文字纵深和
    抠像演示四类路由。每个事件必须有语义触发、进入/峰值/停稳/退出、声音落点、
    失败条件和最简回退，且同时最多一个主效果。
22. **清单模块按效果时长平均弹出**：清单正式渲染必须提供逐项 `itemCues`，
    每项绑定实际口播触发词或可见动作，`revealAt` 严格递增；底层持续存在，
    当前项单独进入和点亮。每项各有一次与可见落位同帧的轻量信息音效，禁止
    在模块开头一次性弹出全部项目，也禁止用一个音效覆盖整组。
23. **自动换行被冒充多行字幕**：常规字幕仍是一行金陵体、无底色、无描边、
    60% 阴影。只有对比、因果、层级或递进关系成立时才能使用多行版式，并为
    每行提供独立 `lineCue`；第一行先落位，第二行在对应口播后再出现。不同场景
    可切换华光标题黑、字号、颜色和排版，但不能因自动换行同时展示两行。
24. **PIP 只是缩小复制主画面**：每个 PIP 必须记录与主画面的信息差；优先放
    外部证据、情境示意、细节、清单或演示素材。同源同内容重复时改用 full-frame
    fit、虚拟景别或移除。PIP 进入、停稳、退出三态都要通过头脸、字幕和平台
    安全区碰撞检查。
25. **粗描边制造廉价感**：常规字幕禁止描边；标题和弹窗默认使用细边界、色块
    层级与柔和阴影，4K 卡片实线边界建议不超过 4 px。只有像素块、蒙版边界或
    明确的印刷语言可以使用可见轮廓，且不能把厚黑边同时套在字体和弹窗上。
26. **外部或生成素材只看风格不看语义**：素材必须逐项核对对象、动作、状态、
    角色、时态和镜头运动；概念画面标注“情境示意”。保存来源、授权、提示词、
    生成模型、文件 SHA 与使用区间。不能用视觉相近但语义不成立的素材填空。
27. **封面人物固定站姿只换标题**：电影级 3D 人物每张封面都必须提交
    `poseContract`，把场景信号、叙事意图、身体动作、视线、表情、道具交互和
    重心变化绑定到当前选题，并冻结动作素材 SHA。`poseAdapted=true` 不能单独
    放行；T-pose、A-pose、证件站姿、对称展示站姿和跨期/跨栏目固定姿势直接
    失败。需要延续同一动作时，必须证明连续叙事关系并改变至少两项动作变量。
28. **开场首帧先露局部人脸小口**：闭合式蒙版、像素窗或 iris reveal 的第 0 帧
    必须是真正全覆盖；首次打开时要么直接覆盖足以识别完整脸/上半身的区域，
    要么改用边缘、条带或块状揭幕，禁止短暂只露眼睛、鼻子或半张脸。代表预览
    必须保留第 0 帧和首次非零揭幕帧作为证据。
29. **把 SFX 文件起点当成声音落点**：每个首分钟和高影响事件必须解码实际 SFX，
    测量短窗 RMS 峰值偏移；时间线起点按 `目标视觉落点 - 波形峰值偏移` 计算，
    并记录 `fileStartSeconds / measuredPeakOffsetSeconds / targetLandingSeconds /
    deltaFrames`。动画起点、素材文件起点和峰值落点不得混为一谈，误差超过 1 帧
    必须阻断代表预览。
30. **首分钟只有“多”没有吸引力和活人感**：`production-quality` 独立审计前
    60 秒，至少 5 个语义动效、4 种机制和 3 个工具实测峰值 SFX；任意 10 秒最多
    3 个主效果。人物在场比例至少 55%，全屏接管最多 35%，呼吸空间至少 20%，
    并保留至少一个真人反应窗口。缺少正常速度代表预览时不得进入 final render。
31. **封面 3D 角色被真人照片重新污染**：默认生成输入必须只有获批 3D 三视图，
    真人照片角色固定为 `post_generation_identity_qc_only`。`kacha cover prompt`
    在动作、表情、视线、重心、道具和服装适配字段不完整时不输出提示词；双锚点
    模式必须逐期显式授权，不能由模型或旧模板自动恢复。

## 13. 性能、Token 与弱模型生产门禁

1. **重复整片编码**：正式视觉版本必须从 Timeline IR 编译为单一 Render
   Graph，完整视频编码最多一次；相同 graph/output 复用时为零次。
2. **探索拖慢交付**：参数探索只允许独立代理或局部区间，区间同时裁切 EDL、
   字幕、dialogue、BGM 和 SFX，并重置同一组 PTS。
3. **高成本步骤重复运行**：Demucs、Whisper、蒙版、跟踪、Beauty、样式帧和
   生成素材必须使用源 SHA、实现 SHA、参数和输出 schema 形成缓存键；
   Demucs/Whisper 还要冻结真实模型内容与服务实现 SHA，强指纹缺失时不允许
   缓存命中；付费生成命中后禁止再次调用。
4. **资源抢占**：默认使用主机级共享锁池，只运行一个重型 MPS 任务和一个
   视频编码；不同项目也不能各建一套锁并同时抢占。不能用并行抢占造成换页、
   掉帧、失败或静默更换后端。
5. **长上下文反复加载**：执行按五类 packet 切分；完整转写和逐词 JSON
   留在文件，agent 按最多 180 秒窗口读取。reference 和完整 packet 超预算
   直接阻断。
6. **弱模型临场猜测**：切镜、景别、连接、字幕、BGM、SFX、美颜和升级条件
   由确定性规则编译；每条规则只返回 1–3 个候选。低置信度或冲突只能局部
   预览并升级，不得 final。
7. **对话冒充状态**：v2 十三阶段、决定、问题、当前文件证据哈希和下一步
   写入 `.kacha/project-state.json`；前置阶段未完成不能越级，合同变化会使
   旧证据失效。续跑从文件恢复，不复制整段对话。
8. **性能收益无证据**：真实命令必须由 `metrics run` 记录时间、Token、缓存、
   编码数和产物；Token 优先读取子进程真实 usage，估算值必须标注。完整日志
   只写文件并脱敏，没有指标时不得宣称提速或省 Token。
9. **执行图按路径误复用**：Render Graph 必须冻结 proposal/edit plan、
   overlay、字幕、dialogue、BGM、SFX、字体与输出合同的内容身份；同路径文件
   原地替换后必须重新编译，已有正式输出不得被无证据覆盖。

## 14. V6 二次深审新增的证据完整性门禁

1. **素材索引只冻结 mtime/size**：index digest v2 必须覆盖完整 SHA-256 文件
   身份、许可、来源、语义字段和扫描完整性；重复 ref、原地替换与重算局部字段
   都不能沿用旧结果。
2. **跨项目拼装各自有效的证据**：manifest 门禁交叉核对 director、asset gap、
   Timeline、perception audit 与 review bundle 的路径、SHA 和 project id；单件
   验证通过不代表证据集一致。
3. **审片 scope 被 CLI 改挂**：项目、栏目、风格和平台只从当前 Timeline 与
   director 重建；candidate video、决策集合与发布边界也必须可重建。
4. **文本文件冒充解决预览或评测成片**：preview/resolution evidence 必须是
   可解码、有视频、有音轨和代表时长的真实媒体；评测输出还要与申报时长一致。
5. **评测重复计样本或错配来源**：同一 source SHA 不能占多个 group；基线与
   候选必须保持 source/show/style/platform 一致，输出完全相同时不能宣称提升。
6. **偏好学习吃入未解决 session 或并发丢规则**：只有 candidate-ready session
   可以学习；activate/rollback 共享 profile 文件锁并保留单调版本历史。
7. **NLE 导入制造新语义身份或覆盖产物**：clip ID 必须来自基线，decision 与
   semantic ID 必须一致；空时间线、重复 ID、短于一帧区间和已存在输出都失败。
8. **后台任务持久化后改命令**：submission digest 固定 argv/cwd/output/
   placeholder/log/pid 合同，读取、执行与状态写入前重新验证；shell 必须为 false。
9. **生产台验证后换文件或 DNS rebinding**：审片服务只接受精确 loopback Host，
   视频在同一 `O_NOFOLLOW` 文件描述符上复核身份并完成 HEAD/Range 读取。
10. **历史遥测拖垮生产台**：观察层最多读取最近 8 MiB JSONL 和最近 500 个 job，
    截断必须写入 integrity warning，不能静默把窗口样本描述成全量历史。
11. **双端安装并发交错**：Codex/Claude `install sync --apply` 使用主机级互斥锁；
    第二个 apply 失败，不能并行备份/替换同一用户级安装。

## 15. V8 效率层深审新增门禁

1. **全局改动却没有代表预览**：`full` 范围必须生成开场、复杂视觉、结尾三段
   人工确认样本；只有 `no_timeline` 可以是零段。
2. **机械分组制造超长预览**：离散变化必须在三段预算内最小化总覆盖跨度，只有
   数学上不可避免的长段才允许 `durationBudgetException`。
3. **重算 digest 绕过质量预算**：计划验证必须从当前 orchestration、cues、
   delta、policy 和 recipes 重建风险、区间、变化覆盖和调度；不能只验证自摘要。
4. **旧 cues/delta 丢失后静默降级**：默认延续证据，缺失时阻断；只有显式
   `--clear-cues/--clear-delta` 才表示主动放弃。当前输入身份另存
   `.kacha/efficiency-inputs.json`；计划和登记同时损坏时禁止自动猜测。
5. **仓库内脚本天然获得执行权**：效率执行器只运行策略登记并有参数校验器的
   确定性脚本，同时绑定当前实现 SHA、执行合同和精确输出。
6. **命令参数写入未声明位置**：参数中的输出必须与声明输出完全一致；执行前后
   都检查项目边界、既有文件和符号链接。
7. **缓存清单与内容键分离**：manifest key 必须等于完整 contract 摘要，输出
   schema、SHA、尺寸和目录文件数均按当前产物重算；路径符号链接一律不可信。
   预热覆盖率只统计阶段计划声明的预期 key，同种类的任意旧条目不得计入。
8. **格式正确的假 SHA 冒充效率证据**：cohort 必须绑定当前可解码源片、含音轨
   审片输出和当前结构化人审、指标、六项护栏文件，缺文件或内容变化即阻断。
9. **重复素材凑够八项目**：两边项目 ID 必须完全一致，同一源 SHA 不能重复计组，
   基线/候选输出必须不同，输出也不能跨项目复用。
10. **状态页信任旧 pass**：`status/observe` 每次重验当前计划与缓存；损坏 JSON
    显示可恢复阻断，`run` 从当前输入重建后才能继续。

## 16. 返工经验统一生产质量合同

上述语义剪切、连接点、开场、效果密度、字幕、清单、PIP、外部素材、BGM、
电影级 3D 封面和正常速度审片要求，不再只作为说明文档存在。新建源视频项目
默认生成 `contracts/production-quality-contract.json`，并在 manifest 中设置：

```json
{
  "productionQualityV1": { "required": true },
  "plans": { "productionQuality": "production-quality-contract.json" }
}
```

三道门禁分别验证不同事实：

- `gate-plan`：规则本身完整且没有把错误做法写成默认值；
- `gate-render`：逐词语义审查、全部最终连接点、唯一开场、逐项清单、语义多行
  字幕、人物身后短词、PIP 信息差、三态避碰、素材语义五元组、专业 BGM 提示词
  和电影级 3D 双身份锚点已经落实；
- `gate-release`：当前 Timeline、dialogue/BGM/SFX/mix stems、BGM 覆盖或有意留白、
  代表段正常速度复核、全片正常速度通看和设备试听都绑定真实 SHA-256 证据。

统一入口：

```bash
node scripts/kacha.mjs production-quality template \
  --project-id PROJECT --output contracts/production-quality-contract.json
node scripts/kacha.mjs production-quality validate \
  --contract contracts/production-quality-contract.json --stage plan
node scripts/kacha.mjs production-quality validate \
  --contract contracts/production-quality-contract.json --stage execution
node scripts/kacha.mjs production-quality validate \
  --contract contracts/production-quality-contract.json --stage release
```

兼容边界：历史 manifest 只有在显式设置 `productionQualityV1.required=true` 时才
强制此合同；所有由当前 `kacha start` 创建的新源视频项目默认强制。合同通过只
证明相应阶段证据齐全，不能把计划验证、静态帧或自动 QC 冒充最终人工验片。
