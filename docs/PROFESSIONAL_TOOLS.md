## 职责与使用场景

| 工具 | 接入场景 | 自动化与回退 |
| --- | --- | --- |
| 咔嚓 | 素材检查、叙事与粗剪、时间线、音频策略、任务恢复、最终 QC | 正式时间线和素材身份由咔嚓维护 |
| AE | 可编辑剪辑装配、标题动画、关键镜头包装；后续按实际需要扩充跟踪/遮罩 | 生成 JSX 工程脚本；空工程中运行，保存独立 AEP；检测到实际 aerender 后才允许提交渲染任务 |
| 剪映 / CapCut | 素材装配后人工/Agent 界面辅助精剪、字幕与局部效果 | 带顺序与时长的独立媒体包；通过当前 UI 操作和观察验证，版本变化后重验 |
| Premiere / Resolve / Final Cut | 已有标准交换入口 | 复用 kacha nle；交换文件生成不等于真实应用往返通过 |

先交付基础剪辑装配桥接，不静默丢失复杂层：原时间线带字幕、转场、混音、蒙版等时，准备阶段应拒绝自动装配并指出未支持项。复杂包装走已批准片段单独工程；完整节目不因某个动效要求强制整体进 AE。

## 实施路线

1. `pro-tools detect`：按真实 bundle ID、版本和文件检测，支持明确指定应用根目录；安装、UI 操作、脚本和渲染是独立状态。
2. `pro-tools prepare`：绑定当前 Timeline SHA 和源素材 SHA，检查帧边界/几何/支持范围，创建独立包，通过已有 jobs 队列生成逐段高质量素材与顺序清单。失败不覆盖原片，可从任务记录恢复。
3. AE 包含可编辑 JSX：每个片段独立图层，保留语义 ID/标记，可选标题动画；保护已打开的非空工程，拒绝覆盖 AEP，不修改脚本权限设置。剪映包提供明确导入顺序与操作清单。
4. `pro-tools status`：复核包和输入身份、准备任务状态、实际应用发现结果；缺软件保持待实机验证。
5. `pro-tools render`：仅 AE；核验实际安装、脚本回执和 AEP，使用 aerender 与既有 jobs 提交。输出失败保留日志，不盲目重复提交。
6. `pro-tools receive`：全片解码、精确帧数/帧率、分辨率、音轨和来源检查后，保存独立候选 Timeline。外部应用工程继续保留可编辑性；回收的视频是扁平化候选，不冒充可逆重建所有效果。原 Timeline 和所有人工审阅状态不覆盖、不继承。
7. 自动技术验收与正常速度人工复核分开；未安装应用不伪造通过记录。实机基础验证覆盖两段剪接、中文标题、音频时间对应、保存重开、渲染回收及取消导出对话框后的恢复；运行中强制中断、长片与复杂效果另验。

## 剪映实机操作结论

- 导入的片段已经裁好，每段从零开始。素材库的添加按钮会在当前播放头插入；逐段添加时先移到上一段末尾，并核对顺序，不能假定始终追加。
- 工程默认帧率可能与素材不同；先修改草稿参数，再读回导出参数。此次保存重开后仍为 25fps，输出切点在第 50 帧。
- 文本与动画必须核对实际预览和导出帧；文字输入成功不代表预览已刷新。此次中文标题与渐显在导出帧中可见。
- UI 控件的可访问性动作有时无效果，坐标输入曾报 `noWindowsAvailable`；重建电脑工具会话后恢复。必须重新观察窗口与焦点，不能在失败后继续盲点或直接宣布成功。
- 回收命令始终保留 `applicationVerified: false`，因为技术检查无法证明应用来源或人工审片。实机操作证据单独记录，并绑定回收媒体 SHA。
- 本次证据保存在本地 `output/pro-tools-2026-10-15/jianying-live/`：`application-roundtrip.json`、`receive-title.json`、`contact-sheet.jpg`；不将私人应用草稿与媒体发布到公共仓库。
