# 像素风视觉语言与动效合同

## 定义

“像素风”是编辑型像素图形语言，不是把真人视频降分辨率，也不是套一层复古游戏
HUD。它用有限色板、整数网格、阶梯边、像素光标、状态条、tile reveal 和离散帧
表达系统状态、步骤、选择与数字变化；真人、证据和正式文字始终清晰。

## 适用与禁用

适用：AI/工具流程、代码与输入、系统状态、步骤清单、倒计时、错误与修复、真实
奖励或里程碑、数字变化、信息从一个状态切换到另一个状态。

禁用：需要辨认人脸细节、医学/法律/财务证据、二维码与小字来源、纯情绪性慢叙述、
没有系统状态变化的普通跳剪，以及任何把严肃失败游戏化的场景。

生产选择必须命中至少一个可核验信号：输入、状态改变、步骤推进、计数、错误修复、
完成确认或真实里程碑；合同同时记录命中的信号和画面/口播证据。没有状态语义时
自动回退 `xingzhe-light-overlay`，不得仅因“科技题材”套用像素包装。

## 视觉合同

- 保留原始实拍；不得像素化人脸、眼镜、手部、证据、二维码、字幕和来源。
- 图形层使用 1080p 下 6–12 px 基准网格、整数坐标、方角或阶梯角和最多 8 色
  强调色板；网格覆盖面积不超过 24%。
- 像素图形关闭模糊插值，正式文字仍在其上方使用授权字体抗锯齿渲染。像素感
  不得通过替换成未经授权的像素字体获得。
- 同屏最多三个像素模块；当前状态最强，下一动作次之，历史状态降权，装饰最后。
- 禁止整屏低清滤镜、持续扫描线、随机 glitch、全屏闪烁和游戏分数占据主画面。

## 动效合同

- 输出仍使用源片原生 FPS 和统一 Timeline IR；像素图形内部按每 2–4 帧一次的
  整数步骤建立，禁止子像素模糊补间。
- `entry`：使用 2–4 个 step、局部 tile reveal、像素光标或状态格逐项点亮；
  不同时弹出全部模块。
- `hold`：完成态完全稳定，不保留扫描、故障噪声或精灵待机循环。
- `exit`：用 2–3 个反向整数步骤或局部 tile clear 清场，最后一格早于下一主
  信息 2–4 帧。
- 数字、错误、奖励和完成状态只有在口播与真实画面同时成立时才能升级为强动效。
- 低能力回退为方角信息卡、一次状态切换或普通干净切，不把静态像素截图贴满画面。

## 音效合同

- 声音母版：`pixel-editorial-quantized-ui`。
- 从项目音效库按真实触发选择 `ui / info / typing / timer / error / knowledge /
  reward`，优先短 UI click、数字 blip、单次 tick、确认或错误提示。
- 声音只对齐状态真正改变的帧，误差不超过 2 帧；同一语义拍最多一个主音效。
- 奖励声只用于真实奖励或里程碑；错误声只用于真实失败；计时声只用于真实计时。
- 禁止复古游戏音乐循环、普通知识点配金币声、不同意见配错误 buzzer、连续提示音
  轰炸和先响后变。

## 240 项效果应用原则

- 字幕与品牌：文字保持正常字体；只让强调块、光标或边界按网格变化，普通字幕
  无音效。
- 标题、定义、金句：使用像素阶梯框、有限色块与清楚停稳，不降低文字清晰度。
- 信息卡、流程与数据：节点/数值按状态逐项更新，未激活区域像素稳定。
- PIP、分屏与人物后文字：使用整数网格边框和 tile reveal，人物前景仍保持
  原始分辨率与干净蒙版。
- 开场与转场：适用于输入、状态改变、错误修复和结果确认；普通连接仍用干净切。

## QC

必须检查：人物、文字与证据未像素化；网格、边缘和运动均整数对齐；强调色不超过
8 色；没有持续 glitch/扫描线；完成态稳定；奖励、错误、计时声音有真实语义；
横竖版独立构图；手机尺寸文字可读；源 FPS、时长和音频时钟未改变。图库门禁还
必须从人物蒙版实测头脸像素未被网格或滤镜改写，并校验网格实占比、常驻品牌尺寸
与动效合同中的选择证据。

完整横竖峰值帧位于
`设计参考/行者风高保真样板/全量效果库_行者风3_像素风/`；每个效果的正式时间行为
以 `config/effects/motion-contracts/design-effect-library-v3.json` 中
`xingzhe-pixel-editorial` 合同为准。
